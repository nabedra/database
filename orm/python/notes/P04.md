## Interfaces for P05

Public `Table` provides immutable `id`, `name`, `key`, `format`, a copying
`schema` property, and `insert`, `insert_many`, `get`, `update`, `upsert`,
`delete`, `query`, `where`, and `drop` with the specified return behavior.
The constructor is `Table(transport: _Transport, descriptor: object)`.
Descriptors must have exactly `id`, `name`, `schema`, `key`, and `format`.
Wire schema types use P01's explicit mapping. UUIDs require the standard
36-character hyphenated form; original case is retained in every request.
The private schema is a mapping proxy around a validated detached copy.

Reusable internal factory:

```python
from meshdb.table import _table_from_descriptor

# _table_from_descriptor(transport: _Transport, data: object) -> Table
transport.request(operation, payload,
                  decode=lambda data: _table_from_descriptor(transport, data))
```

P05 should invoke the factory inside its decode callbacks, including for each
validated list element. It raises ProtocolError, ValidationError, or
LimitExceededError on malformed descriptors, so transport applies read-side
protocol failure or mutation uncertainty. No malformed descriptor indexing
leaks KeyError or TypeError for JSON data.

Terminal query methods can use `query._table.id`, `query._table._transport`,
`query._table.schema`, `query._table.key`, and `query._to_wire()`.
`Table.query()` returns `Query(self)` and `where()` delegates without I/O.
Handles never refresh metadata or redirect requests by name.

Every row operation validates local input with P01 and passes a result decoder
to `_Transport.request`. Null, exact bool, matching exact integer batch count,
and complete schema-valid row-or-null results are checked inside that boundary.
Server errors propagate through transport. Batches count compact UTF-8 encoded
rows incrementally plus commas and the full empty-envelope size, including the
36-character request UUID. Consumption stops on row 10001 or the first byte
limit breach, before any HTTP request. A valid batch, including an empty one,
is submitted once. Transport still enforces its final serialized size.

## Verification

The initial focused run failed because Table and table.py were absent. After
implementation, these exact commands passed from the repository root:

```sh
orm/.venv/bin/python -m unittest discover -s orm/tests -p test_table.py -v
orm/.venv/bin/python -m unittest discover -s orm/tests -v
git diff --check
```

Four compact HTTP test groups and all 23 ORM tests passed. Coverage includes
wire payloads and fixed identity, schema ownership and frozen metadata, query
construction without HTTP, descriptor decoding in the transport boundary,
local validation, missing/conflicting server results, invalid mutation response
uncertainty, empty batches checking table existence, one-request batches,
10000-row success and generator overflow, no prefix transmission, and exactly
8 MiB of UTF-8 request data versus a one-byte overflow.

## Remaining outside P04

P05 owns DB construction/create/discovery/list, terminal query execution and
remaining public exports. Real server/S3 restart, stale-handle drop/recreate,
concurrent storage and trusted-CA integration remain later acceptance work.
The local fixture verifies unchanged IDs and propagation of server not_found;
it does not simulate storage or prove server concurrency behavior.
