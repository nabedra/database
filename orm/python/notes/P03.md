## Internal interfaces

```python
from meshdb.client import _Transport

_Transport(api_url: str, token: str, *, timeout: float = 30.0,
           ca_file: str | None = None)
transport.request(operation: str, payload: dict, *, decode=None)
```

Construction validates configuration and creates a private opener and verified
SSL context without HTTP I/O. It appends `/v1/operations` after stripping trailing
slashes from the base path. Additional CA roots use `load_verify_locations` after
`create_default_context`, so system roots remain available. Timeout applies to
blocking socket I/O, not cancellation or a transaction deadline.

`request` recognizes exactly the 13 v0 operation names and derives mutation
classification internally. Pass `{}` for `table.list`. It sends one POST with a
fresh UUID, UTF-8 JSON and bearer authentication. No redirects or retries occur.
Request encoding and the 8 MiB request limit fail locally before HTTP I/O.
Success and error response reads request at most 8 MiB plus one detection byte.
Responses close before envelope/result decoding, including HTTPError streams.
Truncated Content-Length bodies are treated as lost responses.

`decode(data)` returns the exact terminal result, including converted descriptors
or rows. It must explicitly validate server data and raise P01 `ValidationError`,
`LimitExceededError`, or `ProtocolError` for invalid data. These become read-side
`ProtocolError` or mutation-side `UnknownOutcomeError` inside the request call.
Do not validate a mutation result after `request` returns. Unexpected exceptions
such as RuntimeError/KeyError/TypeError propagate as caller bugs; decoders should
check shape before indexing. Omit `decode` only when raw envelope data suffices.

Exceptions retain the client's UUID even for null-ID server errors, plus HTTP
status when available. Valid server errors preserve code/outcome; unknown outcome
maps to `UnknownOutcomeError` before exception-code mapping. Lost/invalid mutation
responses are always unknown. Successful results are returned directly, without
a wrapper or mutable last-request state. Request IDs provide diagnostics only.

## Validation

The initial transport run failed because `meshdb.client` was absent. Both final
commands passed from the repository root:

```sh
orm/.venv/bin/python -m unittest discover -s orm/tests -p test_transport.py -v
orm/.venv/bin/python -m unittest discover -s orm/tests -v
```

The targeted suite passed 8 test groups. The full suite passed 18 tests including
5 P02 query groups and 5 P01 validation groups present during this run. Tests use
a local HTTP server for wire behavior and small fake streams for closure/read
bounds and injected I/O failures. They exercise preflight rejection, error/status
mapping, null and mismatched IDs, malformed/oversized responses, redirect
rejection, truncated bodies, decoder uncertainty, no retry, and TLS context/CA
configuration. No real AWS or real TLS handshake was used.

Consulted Python 3.11 primary documentation for opener/context behavior:
https://docs.python.org/3.11/library/urllib.request.html and
https://docs.python.org/3.11/library/ssl.html#ssl.create_default_context.

## P03 review correction

Spec review found that malformed HTTP status lines and headers were reported as
read-side TransportError. The coordinator made the small exception-classification
correction. Network/OS failures and IncompleteRead retain TransportError;
other HTTPException failures now use ProtocolError. RemoteDisconnected is an
OSError and retains its network classification. Mutations remain unknown in
both cases.

A real local HTTP regression covers a malformed status line, an oversized
header and a peer disconnect, for reads and mutations. The malformed-status
case reproduced the wrong exception before the fix. The full ORM unittest
command above now passes all 19 tests. Independent re-review remains pending.
