# R05 table catalog lifecycle

Implemented only `src/engine.rs`, `tests/engine_catalog.rs`, and this note. No lib/Cargo/config/CLI, protocol, snapshot, commit, pure query/mutation, or implementation-plan changes. No AWS, secrets, delegation, branches, worktrees, commits, or pushes.

## Interfaces and contracts

`Engine<B: ObjectStore>::new(Storage<B>) -> Engine<B>` consumes already initialized storage. Call once per engine and clone it. Manual `Clone` shares one `Arc<Coordinator<B>>` and requires no `B: Clone`. There is no table/row cache or per-operation coordinator. Accessors are `coordinator(&self) -> &Arc<Coordinator<B>>` and `storage(&self) -> &Storage<B>`. Later mutations must use the shared coordinator, never direct storage PUTs.

All operation methods take `&self` and return `Result<T, ProtocolError>`:

- `create(CreatePayload) -> TableDescriptor` accepts the existing owned protocol payload. Under a fresh global mutation session, it awaits protocol schema/name/key validation on a blocking worker, rejects duplicate names, generates an independent table UUID, then awaits empty Parquet encoding on another blocking worker. `TableFormat` admits only Parquet. The candidate records zero rows and the canonical table/session commit snapshot path. R04 publishes snapshot then catalog and confirms publication before return.
- `describe(String) -> TableDescriptor` validates the identifier, loads the catalog exactly once without acquiring the mutation lock, and returns the exact owned descriptor or not_found.
- `list() -> Vec<TableDescriptor>` loads the catalog exactly once without acquiring the mutation lock and returns ascending name order from the catalog's BTreeMap.
- `drop(Uuid) -> ()` resolves only the immutable table ID under a fresh mutation session and removes exactly that entry. It publishes only the catalog with `None` snapshot. Unknown/stale IDs return not_found; old snapshots remain. The transport can construct its specified success payload from the unit result.

These success values and ProtocolError are serializable. Duplicate names return conflict/not_applied. Blocking task join failures return sanitized internal_error/not_applied before publication. Codec and coordinator ProtocolErrors retain their classifications, including limits and publication uncertainty. Fresh read byte limits return limit_exceeded; missing/corrupt/unavailable metadata returns storage_unavailable. No operation initializes or repairs catalogs. Private error helpers are local to engine.rs.

## Exact R06 obligations and later work

After R10b releases lib.rs, R06 must export `pub mod engine` and declare the existing pure `query` and `mutation` modules within engine.rs as appropriate. R05 intentionally declares neither child module and adds no partial operation dispatcher. R06 can extend this Engine and use its coordinator accessor for row mutations and its storage accessor for fresh reads. Adapt executor dispatch to the four owned-input method contracts above. Keep table IDs immutable and share this same coordinator across every engine clone.

R06 owns bounded snapshot reads, sequential awaited blocking validation/codec work, row CRUD/query behavior, and complete response-size accounting. Startup must initialize storage before constructing Engine. The later executor must retain and await admitted mutations across cancellation/disconnects, including all blocking jobs; Engine owns no runtime, detached task, timeout or admission policy. HTTP, CLI/startup wiring, response envelopes and S3 acceptance remain outside R05. R03 decoder footer re-review remains independent; R05 changed no codec code.
