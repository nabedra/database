# DN-A07 private enrollment and HTTP contract

Design only, accepted by the parent on 2026-11-11 after the independent design re-check passed. Resolve the private boundary needed by R03/R04/R07 over [shared contracts](../../plans/distributed-contracts.md), accepted [A05](DN-A05.md) and [A06](DN-A06.md). This note explicitly supersedes A05's original secret-hash verifier and enrollment-derived shared message key without changing Node.session fields. Preserve `serve`, `Cluster`, worker CLI, one backend and identical workers. This note adds no public methods, provider dependency, controller design or acceptance framework.

## Credential correction for parent reconciliation

A05's enrollment-derived shared key plus signed scope labels cannot prove the sender's role or possession of a particular session secret. Every worker retains the enrollment secret and can derive that key for another incarnation, or claim the API role. Checking current membership rejects an honestly labeled retired session, but cannot prevent that process forging a current label. A stored digest used as a MAC key/bearer would also turn metadata access into credential possession.

Use standard Ed25519 signatures for private request authentication. Each boot generates a random 32-byte session seed before registration and keeps it only in memory. Its public key is 32 bytes. Change only A05's verifier formula to `SHA256("meshdb.worker-verifier.v1\0" || cluster_uuid_bytes || node_uuid_bytes || incarnation_uuid_bytes || session_uuid_bytes || public_key_bytes)`. `Node.session` remains exactly `{id, verifier}`. The random seed is the session secret, never sent or persisted. Public keys travel with signed requests; the verifier is never a credential. No raw enrollment or session secret enters shared storage, diagnostics or public status.

Compatible APIs derive one cluster API signing seed with standard HKDF-SHA256: salt is the 16 cluster UUID bytes, input is UTF-8 `admin_token`, info is ASCII `meshdb.api-signing.v1`, output is 32 bytes. At least 256 bits of generated entropy in the existing admin secret is a deployment requirement; length or syntax checks cannot establish entropy. Workers never receive it. This adds no secret/config field. Enrollment replies pin the derived API public key in worker memory; API replicas derive the same key. The API signing role permits operation routing, readiness and drain only, never bypasses public admin/data authentication or A04 callback authorization.

Use cached/locked `ring = "=0.17.14"` directly for `SystemRandom`/`SecureRandom::fill`, `Ed25519KeyPair::from_seed_unchecked` with an exactly 32-byte generated seed, `sign`, `UnparsedPublicKey::new(ED25519, ...).verify`, HKDF and SHA256. These APIs were inspected locally. The parent approves adding this exact direct dependency and its root lockfile dependency entry in the assigned implementation slice. `ring` is currently only transitive. Do not implement crypto primitives or fetch dependencies. This design makes no Cargo edit; A06's independently approved sha2 dependency remains its owner's work.

This rejects an old process using its old signing seed/session against a fresh durable binding. It does not isolate malicious cluster members with shared backend write credentials or the global enrollment secret: they can corrupt metadata or request new external enrollment. Manual enrollment is an operator trust boundary. Plain HTTP additionally trusts the network. Arbitrary compromised-member isolation, per-node enrollment credentials and credential rotation are outside scope. Expiry alone does not revoke a submitted catalog CAS; retain C02 root-token/decision fencing.

## Enrollment and recovery

All new control JSON is object-only version 1, duplicate/unknown-field rejecting, required-null, canonical UUID and exact integer syntax as A05. Hex is lowercase, with exactly twice the decoded byte length. URL/capacity/template bounds are A05's. Enrollment request/reply and all small exchanges below each have a 16 KiB encoded cap and depth 16. Errors use existing sanitized `{request_id,error:{code,message,outcome}}`, with null request_id when unavailable. Authenticate credentials/signatures before operation-history lookup or effects; reading durable Control to establish authorization is permitted after bounded handler admission and signature validation.

`POST /internal/v1/enroll` is an API-listener route reached through bootstrap `api_urls`. It uses exactly one `Authorization: Bearer <enrollment_token>` and `Content-Type: application/json`. Enrollment is the only internal route accepting that token. Body:

```text
{version:1, cluster_id:UUID, node_id:UUID, request_id:UUID|null,
 incarnation:UUID, session_id:UUID, public_key:hex32,
 endpoint:URL, operation_slots:1..256, partition_slots:1..256, queue_size:0..4096,
 proof:hex64}
```

`proof` signs ASCII `meshdb.enroll.v1\0` followed by compact JSON of the other fields in exactly the displayed order. Reconstruct with one Rust serializer after strict validation. Generate incarnation, session_id and seed once per process boot, before the first send. Retain identical enrollment values across retries and API failover. Listener binding, bootstrap/storage/catalog validation precede enrollment. The worker remains closed to execution until it knows its registration committed.

Success is HTTP 200 with exactly `{version:1,cluster_id,node_id,incarnation,session_id,registration:"registered"|"verified",api_public_key:hex32}`. A ready member reports verified; drainage is never recovered as readiness. Reply contains no new secret. The worker checks every echoed identity and pins the API key through verified TLS, or the explicitly trusted local HTTP channel. Enrollment replies are exempt from the signed worker-response envelope below. The worker permits execution only after recovering its committed binding and pinning that key, and only while current durable eligibility permits it. Earlier readiness attempts fail closed and may be retried.

The receiving API checks enrollment authentication and key possession before storage effects. Only the current controller performs A05's owner-checked CAS; another replica returns 503 storage_unavailable with not_applied and a static ownership-unavailable message, without registering. The worker can retry the identical enrollment against bootstrap api_urls under bounded backoff and its startup/recovery budget. This version adds no API-to-API forwarding protocol. First managed registration requires exact retained node/launch/template/capacity matching, an unregistered starting or draining member, and a start intent in in_progress or reconciling with retained dispatched-delivery evidence, or completed with outcome resource_known. Pending, failed, unknown, quarantined, lost and stopped launches are ineligible. The registration deadline bounds ordinary launch/readiness progress; expiry neither invalidates a retained unresolved launch nor alone marks its unregistered member lost. After expiry reconcile that same identity without allocating a replacement. Registration may precede resource recovery and grants no readiness. A draining registration stays draining, accepts no execution and exists only to complete authenticated drainage. External mode requires request_id null, null launch_id and external ownership, creates `external:<node_id>` and never invokes callbacks. An external replacement requires durably lost/safely stopped prior incarnation, retirement-room checks, fresh incarnation/session, and reset verification/drain.

An exact same-incarnation retry must match session_id, computed verifier, endpoint, capacities and launch identity. It recovers the existing starting, ready or draining binding regardless of deadline, preserving session, endpoint, verification and drain state. It never revives lost/stopped/retired identities or changes fields; different values conflict. After an uncertain CAS, reload and recognize that exact binding; if absent, recompute using A05's fresh-token rules. Dropping the HTTP acknowledgement immediately before drainage therefore needs no durable secret/result cache. Initialization failure never produces registration or idle proof. Without successful initialization and authenticated drainage, an unresolved resource remains stalled unless positive termination evidence resolves it. A process that loses its seed cannot recover that incarnation and must follow replacement rules.

Readiness uses the signed probe below against the registered endpoint, after resource identity is attached. The target checks its own in-memory identity against fresh durable registration, performs initialized endpoint/storage checks and signs the caller's fresh challenge. The controller verifies the response key against Node.session.verifier and exact challenge/target, then CASes verified/ready only if the binding/resource/phase still match. Reusing the address, opening a port, a public health response or a response from another boot proves nothing.

## Signed HTTP envelope and role checks

Except enrollment, every private request has exactly one `MeshDB-Auth` header containing lowercase hex of compact UTF-8 JSON `Auth` below, at most 8 KiB of header value, and exactly one `MeshDB-Signature: <hex64>`. No Authorization bearer is accepted on these routes. Sign ASCII `meshdb.http-request.v1\0` followed by the exact decoded Auth bytes, validated and re-encoded identically in this field order:

```text
Auth = {version:1, cluster_id:UUID, scope:Scope,
 sender:{role:"api"|"worker", process_id:UUID, node_id:UUID|null,
         incarnation:UUID|null, session_id:UUID|null, public_key:hex32},
 receiver:{node_id:UUID, incarnation:UUID, session_id:UUID},
 sequence:positive_u64, method:"POST", path:Route,
 operation_id:UUID|null, admission_id:UUID|null,
 job_id:UUID|null, attempt_id:UUID|null, request_digest:Digest|null,
 control_sha256:Digest, dependency_id:UUID|null}
```

For workers, process_id equals incarnation and every sender identity is nonnull. Freshly GET Control before accepting each request, verify sender public key against the current verifier, incarnation/session and eligible phase, and compare receiver to both durable and local identity. Lost/stopped/retired identities fail. A draining sender may only finish dependencies under its retained admitted operations. API sender process_id is a fresh boot UUID, other identity fields null, and key must equal the enrollment-pinned API key. Only the API key permits role api. All scopes bind method/path and cluster; query strings, alternate path spellings and redirects are rejected. Storage uncertainty fails closed with 503. No positive membership cache grants authority after revocation. Operation/open target must be verified/ready; jobs require verified/ready or a draining target with an existing permit. Close is allowed while draining. Authorization observes the linearizable root GET; revocation racing after that GET does not retroactively cancel an admitted request. Recheck eligibility before starting queued execution and accepting results, and retain the database publication fencing rules for effects already submitted.

Maintain a high-water sequence per sender identity/key and receiver session across all routes, under the same local admission lock. Senders allocate checked increasing sequences for that target; reject <= high-water before effects. Reordering may reject a request. Such a rejection describes only this transport attempt and proves nothing about an earlier attempt's effects. A new-sequence retry is allowed only by the route's existing retry rules. Uncertain mutations retain the original request UUID and exact bytes and use C02 decision reconciliation; transport never automatically resends them. Pure-job retries preserve logical identity and follow the existing attempt-identity rules. Keep entries until receiver boot ends, at most 2048 worker sessions and 128 API process identities; refuse new identities on exhaustion, never evict replay evidence. Worker restarts have fresh receiver incarnation/session, so captured requests cannot replay to the replacement. Sequence exhaustion stops sends. This is transport replay rejection, not operation deduplication.

Bound handler admission before authority-storage reads. Validate header syntax and signature first, then resolve durable authorization, then poll bounded body content. No pre-authentication body collection, spool allocation or compute admission is permitted. `control_sha256` binds the exact small JSON body, exact original public operation bytes, or the exact first job CONTROL payload. Read/hash that bounded content and compare before effects/compute admission. Do not serialize streamed rows or Parquet into Auth or a signature buffer. HTTPS provides integrity for the entire request/response byte stream, including DATA/PART_META and body framing; A06 still checks semantics and prepared-file digests. Plain local HTTP has no hostile-network payload-integrity guarantee.

Every authenticated response from a worker-listener route has the same two headers, with Auth replaced by `{version:1,cluster_id,request_sequence,scope,sender,receiver,status,control_sha256}` in that order. Sender is the exact worker identity/key, receiver is the original sender object, and signatures use domain `meshdb.http-response.v1\0`. The client verifies the current worker verifier, exact request association/status and bounded initial content hash before accepting output. TLS and A06 validate the remaining stream. Enrollment uses the API reply exception above. Unsigned pre-auth errors give no authenticated outcome. No secrets or raw headers enter logs.

## Routes and bodies

The following table describes worker-listener POSTs; enrollment remains on the API listener. `scope` is exactly the table value. All unused Auth operation/admission/job/attempt/digest fields are required null. Small responses are application/json and strict JSON; success status is 200. A job success/error is the existing framed result, not another data protocol.

| Route / scope | Allowed sender; body and success body |
| --- | --- |
| `/internal/v1/operations` / `operation` | API only. Exact existing public request bytes, <=8 MiB, application/json. Auth operation_id equals request_id and request_digest hashes those original bytes; admission/job/attempt null. Existing encoded public response, <=8 MiB, with original durable outcome semantics. |
| `/internal/v1/jobs` / `job` | Worker only, matching an open dependency permit below. Existing Frame v1 request/result, `application/octet-stream`. Match nonnull operation/job/attempt/request_digest against CONTROL; match admission_id and dependency_id against the retained permit. Hash the exact first CONTROL payload bytes before parsing or reserialization. Use `parse_job`/`parse_result(expected)`; captured snapshot/ordinal/descriptor/task remain bound through the CONTROL hash and existing validators. |
| `/internal/v1/readiness` / `readiness` | API only. `{version:1,challenge:UUID}`; reply `{version:1,challenge:UUID,initialized:true}`. All execution IDs null. Valid only for starting registered or ready target, never revives draining/lost/stopped. |
| `/internal/v1/dependencies/open` / `dependency_open` | Worker coordinator only. `{version:1,permit_id:UUID}`; reply echoes it. Auth operation/admission/digest nonnull, job/attempt null. Target must still admit new work. |
| `/internal/v1/dependencies/close` / `dependency_close` | Same coordinator binding; body `{version:1,permit_id:UUID}`, reply `{version:1,permit_id:UUID,closed:bool}`. Mark closing and refuse new jobs; return closed:false while accepted owners remain. Release the record and return closed:true only after those owners finish. An already absent record returns closed:true without proving any earlier execution history. |
| `/internal/v1/drain` / `drain` | API only. `{version:1,drain_id:UUID}`; reply `{version:1,drain_id:UUID,barrier:true,idle:bool,heartbeat_sequence:positive_u64}`. IDs null. Fresh durable root must name this exact draining target and drain_id. |

Job Auth admission_id identifies the coordinator's operation admission, and its initial CONTROL remains unchanged. Carry the target permit UUID in exactly one `MeshDB-Dependency: <canonical UUID>` header on jobs. Auth dependency_id must equal that UUID; it is null on other routes. Open/close body permit_id must match the receiver's retained mapping, not a coordinator claim about target occupancy. This extra field/header is transport metadata, not a job DTO/codec change. CONTROL and PART_META retain their 16 MiB bounds, DATA retains 64 KiB, and row arrays retain their separate internal allowance. The 16 KiB small-exchange cap does not apply to job CONTROL.

Existing API response encoders/error codes apply: 401 invalid auth/scope/target, 409 identity/barrier conflict, 413 bound, 429 admission saturation, 503 authority/storage/unavailable. Reject before execution with not_applied; connection loss after operation admission may be unknown. Job failures make no database outcome claim. Health routes remain boolean and grant no execution authority. Heartbeats remain A05's direct conditional backend records; add no heartbeat HTTP service. A04 `/private/v1/authorize` remains a separate lifetime-authenticated loopback service.

## HTTP ownership, bounds and progress

Use existing Axum/Hyper HTTP/1 facilities and storage/http.rs URL, verified-CA, no-proxy/no-redirect/no-retry patterns. Private base URLs have no path prefix. HTTPS loads configured CA roots and verifies chain and DNS/IP SAN against the URL, including loopback; server loads validated cert/key. No insecure verifier or HTTPS downgrade. `tls:null` explicitly opts into trusted local/private HTTP and must agree with advertised URLs; local runner uses numeric loopback only. Cross-host hostile networks require HTTPS. Enrollment pins API verification key through this channel, not through unauthenticated discovery.

Small JSON/operation requests and responses require exactly one decimal Content-Length within their cap; reject Transfer-Encoding, trailers, compression and ambiguous duplicate framing. Jobs use HTTP/1.1 chunked bodies with exactly one `Transfer-Encoding: chunked`, no Content-Length, trailers or compression. HTTP chunks and Frame v1 chunks are independent. Inspect HTTP body frames and reject trailers before converting DATA into AsyncRead; preserve body errors through the reader. Do not use BodyDataStream directly: its omission of non-DATA frames would hide trailers. FrameReader's real EOF means successful HTTP body end, not TCP closure. STREAM_END without terminal HTTP chunk, extra body bytes after STREAM_END or early Content-Length exhaustion fails. FrameWriter::finish emits STREAM_END; its owner must then finish the HTTP body. Set Connection: close, one exchange per connection, no upgrade/pipelining/reuse after cancellation. Normal HTTP framing owns the outer EOF; never wait for peer TCP close to accept a chunked body.

Defaults are explicit runtime constants, privately injectable for focused tests: 5s DNS/connect/TLS, 5s complete HTTP headers, 30s total small exchange, 30s maximum interval without body progress and 300s total operation/job exchange. Each uses monotonic deadlines; nested calls take the smaller remaining owner budget. Partial bytes never reset the total deadline. Header cap is 16 KiB/32 fields and accepted connections are at most 64 per listener. Bound unclassified header assembly to 24 connections, operation exchanges to 16, dependency-job exchanges to 16, and control exchanges to 8; classifications transfer ownership without exceeding the total. These limits never borrow from one another. Control includes enrollment on the API listener and readiness/drain/dependency-open/dependency-close on worker listeners. Waiting coordinations cannot consume reserved job transport or control capacity. No unbounded transport waiters are allowed; excess closes/429 before body polling. Header assembly has deadlines and no body prebuffer beyond the HTTP parser's bounded buffer. Listener saturation remains a bounded availability limit, not a denial-of-service guarantee.

Acquire transport admission before polling bodies, opening spools or creating supervisors. After authenticated control parsing acquire the distinct bounded operation/partition queue admission; never queue a whole network round trip on WorkerPool. Control handlers do no partition work and use neither compute budget. Preserve A06's finite CPU/I/O commands, separate executor, one supervised owner, cancellation/drain/cleanup and retained transport/quota permits until accepted commands actually finish. Deadlines stop further transport activity, not an already submitted database CAS or synchronous command. Disconnect after admitted mutation keeps durable-completion ownership. No per-frame spawn_blocking, unlimited waiters or detached cleanup.

## Drain permits and positive idle proof

Operation admission allocates a fresh admission_id held until coordination, publication resolution and cleanup finish. Under the same local lock it opens an implicit self dependency permit. Before dispatching any peer work, that coordinator opens one permit per intended target while that target is accepting, with binding `(coordinator node/incarnation/session, operation_id, admission_id, request_digest, permit_id)`. Target retains at most 4096 permit records in total, including self, open and closing permits; exhaustion refuses new opens. Exact open retries converge on an existing open binding, and mismatched reuse conflicts. A closing permit cannot be reopened. The coordinator serializes open/close for each target, uses a fresh permit_id per admission, and never retries open after initiating close. Closed records need no tombstone: captured opens fail the session sequence check, and new opens after the barrier always fail. This relies on the stated trusted-coordinator rule, not protection against a malicious member signing a new open. A trusted coordinator opens only for a live admitted operation. Authentication proves the caller identity, not the honesty of this claim; the receiver's pre-barrier record supplies the ordering evidence.

The target's local barrier lock serializes operation admission, permit open and drain. A fresh durable draining state already denies new operations/opens even before drain HTTP arrives. Drain closes admission permanently for this incarnation and drain_id. Afterward, refuse new operations and all jobs except jobs matching a permit recorded before the barrier, including the implicit self permit. Those jobs may acquire partition admission after the barrier; they never acquire an operation slot. Opening a new permit after the barrier for an older operation is refused, so coordinators reserve their planned targets before dispatch or fail/reroute through existing operation failure rules. Timestamp assertions or operation UUIDs alone grant no exception.

Close marks a matching permit closing under the admission lock and refuses new jobs. Accepted jobs retain their existing ownership; closing does not revoke them. Return the bounded closed:false response while accepted jobs, deliveries or cleanup remain, without occupying a control handler waiting for completion. Matching retries converge. Release the record only after all such owners finish; an absent record returns closed:true but grants no authority or evidence that it ever existed. Coordinator closes only after it will dispatch no more dependencies and all accepted attempts settle. Loss of a coordinator/close reply cannot invent idle evidence; close may be retried with a new transport sequence. No timeout, membership expiry or absent close record proves completion of remote work. An unresolved permit can stall drain after its deadline, with no forced provider stop. Self permit closes with the owned operation, including self-dispatch cleanup. This bounds drain evidence without a distributed operation registry.

Drain replies are immediate bounded observations, not long polls. `idle:true` requires closed barrier, zero running/queued operations/partitions, zero open dependency permits, zero delivery/validation/cleanup supervisors and no unresolved publication owner. Worker first publishes an A05 heartbeat at/after that barrier and returns its sequence. A false observation keeps drain pending. Controller authenticates exact target/drain/sequence, checks durable binding and heartbeat, then CASes A05 ack_seq/confirmed_idle. Takeover re-probes; any later nonzero observation clears proof. Provider stop requires A05's fresh owner/intent authorization and this exact proof, never timeout or generic idle metrics. It proves this worker has no admitted work capable of further effects and cannot accept more, not that wall-clock expiry revoked a database write.

Adopted [A21](DN-A21.md) refines that drain observation: only the exact current
memory-only drain-control record and response transport may be excluded from
work-idle; they remain retained and must still reap for shutdown. Its proof
heartbeat publication is separately owned through settlement/reaping and cannot
be excluded merely because its write was acknowledged. R04 rechecks actual
owners after that settlement; the proof-only heartbeat lifecycle does not itself
invalidate the work-generation sample. No other accepted work or cleanup is
excluded, and whole-process shutdown keeps the full ownership requirement.

## Parent correction after independent design review

The first review accepted per-boot Ed25519, API HKDF derivation, scoped signatures,
bounded replay evidence and dependency permits within the explicit trust limits,
but rejected adoption until seven concrete gaps were resolved. The parent made
those corrections in the sections above: retained late/draining registration;
API enrollment placement and response exception; independent operation/job/control
transport admission; nonblocking closing permits; uncertainty-aware sequence
retries; unchanged job CONTROL identities/bounds; and trailer-preserving HTTP body
inspection with bounded authorization ordering. Entropy is a deployment
requirement, not an inferred property of a string. Noncontroller enrollment
returns a bounded 503 rather than introducing unspecified API forwarding.

The concrete default ingress split is 24 unclassified connections, 16 operation
exchanges, 16 dependency-job exchanges and 8 control exchanges, within a total
64. Closed/pending permit replies use the exact closed boolean above; the 4096
permit bound includes self and closing records. The fresh independent design
re-check passed with no remaining concrete blocker to adoption. It inspected the
corrected contracts and existing interfaces without builds, tests or edits.
The parent adopted this note and explicitly superseded A05's old verifier formula
and shared message key. No runtime code, test result or distributed guarantee is
established by this design review.
