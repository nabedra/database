## Source facts that determine the boundary

`PayloadOwners::Shared` has a private registry mutex, coordinator WorkerPool and injected operation/operation-transport/dependency-transport semaphores. `register_with` reaps, checks closure/parent, try-acquires capacity, increments the ID, allocates Slot/channels, spawns a registration-gated supervisor and inserts Entry. It can refuse; it is not an infallible install primitive. Entry retains JoinHandle and ManuallyDrop admission guards. Disk is in a separate disposal-only cell. `reap` releases guards only after cleanup and successful handle termination. Pool-stop failure retains guards and disk. Preserve these properties.

`try_bound_operation` binds operation UUID after `try_operation`; `try_local` validates/encodes before registration and takes external execution/queue semaphore permits. Neither is the atomic distributed operation/self-permit constructor. LocalOutput's worker-only deposit and `engine::run_captured` already provide the typed execution seam; do not expose their private raw owners.

`payload_stream::drive` reads CONTROL and submits BeginRequest/BeginResult, which parse it. Its receive functions already require PayloadLease. They cannot be called as a pre-authentication entry point or consume an already-read checked CONTROL without a later explicit adaptation. FrameReader requires STREAM_END plus actual EOF; cancellation poisons partial operations. Spool creation and final Root/operation/file destruction perform synchronous filesystem work.

WorkerPool bounds each thread's accepted queue to one, but not callers waiting in submit. Job observer Drop does not cancel accepted work. Standalone Executor admits workers+queue and detaches tasks; its Admission can release before a buffered task result/cleanup owner is reaped. Executor and runtime::serve therefore do not establish A09 distributed ownership. Leave them unchanged. Member capacity validation already requires separate operation/partition workers in 1..256 and queue_size in 0..4096; standalone ServeOptions/Executor validation is not the distributed configuration authority.

Unchanged content/eligibility code supplies associated checked proofs and typed PendingLocalChecks. DependencyBinding retains complete coordinator Sender, operation/admission UUIDs and digest; Jobs additionally retain permit/job/attempt IDs. ReceiverIdentity compares cluster/node/incarnation/session/key. Durable checks are provisional: they do not prove initialization, local barrier, permit existence, replay or capacity. Do not replace these predicates with caller booleans.

## Fixed ownership rules for all three minis

Use one `Arc<Mutex<ReceiverState>>` for distributed receiver state. It contains full-root/replay ordering, immutable exact boot identity, local initialization/barrier, operation/partition capacities, dependency records and accepted-owner/handle registries. Payload disk cells and their short cancellation locks remain separate; they contain no admission authority. No replay-only mutex followed by payload registration. No arbitrary closure transaction API.

Allocate bounded table storage and memory channel/task preparations outside the receiver critical section. Under it do bounded identity lookup, state changes, handle polling and memory moves only. No body/header parsing, root encoding/hash, RNG, storage/disk calls, WorkerPool submission, await, blocking thread join or long Tokio CPU polling. Generate UUID candidates and prepare complete OwnershipObservation on the bounded coordinator CPU/I/O pool before locking. Reject checked counter exhaustion before replay. An integrity failure is sticky for this boot.

All fallible live checks/reservations precede consume. Commit installs an already prepared accepted owner synchronously, without a new try_admit, task spawn or channel allocation. Ordinary allocator abort/runtime destruction is outside the completion guarantee; do not turn a recoverable refusal into an alleged infallible commit.

A request observer is a move-only cancellation/use handle, never the lifetime owner. Observer Drop signals existing ownership and does no spawn, filesystem work or guard release. Registered entries retain capacity, dependency uses, transport ownership, publication handles and task handles through submitted work, buffered replies, delivery, disposal and actual reaping. Cancellation requests settlement; it does not assert it. Failed cleanup/failed drain quarantines original entries and guards and prevents positive idle.

## Mini 1: local barrier, dependency and capacity ownership core

Own only new `server/src/node/admission.rs`, its embedded private tests and the private admission module line in node/mod.rs. No auth, payload, executor, pool, runtime, controller or Cargo edits. This mini has no final authenticated acceptance API. Its private state methods will later be called only inside the enclosing receiver transaction.

Define concrete private `LocalAdmission`, `Capacity`, `WorkKey`, `WorkRecord`, `WorkPhase`, `DependencyRecord`, `DependencyUse`, `Barrier`, `InitState`, `Occupancy` and `LocalSnapshot`. Keep checked capacities as integers, not fake semaphore availability. Reserve fixed tables at construction: O=operation_workers+queue_size operation entries, P=partition_workers+queue_size partition entries, and exactly 4096 total dependency entries including self/open/closing. Each table has checked monotonic IDs or generations; no stale ticket can address a reused slot. Refuse exhaustion without mutation. Construction validates both worker counts and queue bound independently.

`reserve_operation(binding, admission_candidate, self_permit_candidate)` reserves one operation record AND one implicit self record atomically. Binding includes exact local coordinator identity/key, operation UUID and digest. Reject uninitialized, durably ineligible, permanently closed barrier, full capacity, dependency exhaustion or ID collision. Fresh admission_id is distinct for each acceptance; transport replay is not operation deduplication. An operation owns no partition token while coordinating/awaiting peers.

`open_dependency(binding, permit_id)` converges only on an exact existing open record. Mismatched reuse conflicts and closing never reopens. A new record requires current initialized/ready admission and no local/durable barrier. Check complete coordinator node/incarnation/session/key, operation/admission/digest and permit ID, not operation UUID alone. Trusted coordinators serialize open/close, use fresh permits per admission and never open after initiating close. No tombstone, malicious-member protocol, TTL eviction or lost-coordinator cleanup is introduced.

`reserve_partition(binding, permit_id, job_id, attempt_id)` requires an exact open dependency and increments its live-use count in the same reservation. After the barrier it still accepts matching pre-barrier self/peer permits under the current typed durable predicates. It never reserves an operation record. Closing refuses new uses. Attempts have owned identities, not an implied retry/deduplication policy.

Capacity admission picks RunningReserved when a worker charge is free, otherwise Queued if its separate queue has room, otherwise refuses immediately. A running reservation counts toward running occupancy before execution starts. Queued entries count only toward queued occupancy. `next_start(kind, StartCheck)` promotes one owned queued entry only when a running charge is free; it returns a move-only StartTicket after current-root/boot/barrier/dependency rechecks. A closing permit blocks new admission but does not revoke an accepted use. There is no unbounded acquire waiter list. Retain running/queue charges conservatively through settlement and reaping, so delayed cleanup may reduce throughput. Expose phase-transition methods, not public decrement/set-count methods. StartCheck is a private move-only receipt issued by admission.rs after fresh typed checks outside the lock. It binds the WorkKey/generation, retained request identities, exact boot and complete new root observation. next_start checks that receipt against current state under the same lock; a superseded check cannot start work. There is no bool/raw constructor available to callers. Mini 1 tests construct it inside their private fixture; mini 3 owns its production issuer using the checked durable view below. Actual dispatch is later; mini 1 tests real reservation ownership, not engine scheduling.

`begin_close(binding, permit_id)` marks Closing and immediately returns Pending while any accepted use, delivery or cleanup survives. The last actual owner reaping removes a closing record. A self record also stays open for its owned operation, then closes when dispatch is finished; operation publication and self-job cleanup must settle before removal. Absent close returns Closed without proving earlier remote completion. No timeout, membership loss or heartbeat expiry releases an unresolved open/closing record.

`observe_drain(exact_boot, drain_id)` permanently closes operation/open admission for that incarnation; a different ID conflicts and repeated exact drain converges. Fresh durable draining observation closes admission even before drain HTTP arrives. Closed never reopens on a later ready-looking observation. Queue-start checks still permit accepted dependency progress. Missing/replaced/lost local durable association denies execution and fresh admission, retains unresolved owners and cannot produce successful drain.

InitState starts Uninitialized. Construction reserves one boot-bound initialization identity, retained through success or failure; it is not a readiness flag. Mini 2 supplies an opaque ProcessReady receipt only after the registered process anchor's worker initialization command settles successfully. That receipt retains the exact boot and process-entry identity, without a raw Spool owner. The later R07 worker-startup owner must supply its opaque InitializedWorker completion from successful configured storage/catalog initialization, bound to that same boot and initialization identity. Its private construction belongs to the R07 startup module, never to HTTP/auth callers. Admission consumes both receipts and checks the still-retained process entry before issuing/consuming its one-use InitializationReceipt under the receiver lock. Failure or cancellation retains unfinished initialization ownership and cannot mark initialized. This pins the production completion seam; mini 1 defines the retained identity/state, mini 2 the process receipt, and R07 owns the concrete storage/catalog completion and final wiring. Until R07 exists, only private fixtures can complete that missing half. Do not add initialized(bool), a success enum supplied by a listener, or an unchecked public receipt constructor. A readiness query compares exact boot/current durable eligibility and reads initialization state, then echoes the checked challenge. It cannot set initialization or Ready. Later authenticated probe/C03 ready CAS remains mandatory.

Tests use real RAII reservation records, scoped threads/events and bounded owner tables: saturate each budget independently with queue=0 and nonzero queues; reject the next owner; release/reap before proving reuse. Gate a genuinely accepted queued record, supply an independently checked newer authority sample before next_start, and verify refusal retains its original record and charges until settlement. Close the barrier against an operation/self allocation and peer open, then finish matching accepted self/peer jobs while rejecting new operations/opens. Explicitly promote an already accepted queued job after its permit becomes closing; closing rejects new uses without revoking that accepted use. Close with a retained job/delivery use must return Pending until its owner settles. Exercise dependency bound including self/closing, mismatched retry and exact open convergence. Mini 3 repeats only the typed-authentication composition of the queued-start case. Do not claim same-sequence or payload cleanup evidence here.

## Mini 2: payload memory reservation and common registry lock

Depends on reviewed mini 1. Own only additive admission.rs receiver-container definitions, payload_owner.rs registration/reaping adaptation, embedded/private payload_owner tests, and narrow node/mod.rs access lines. No payload_stream, frame, spool, job, engine, WorkerPool, executor, runtime or auth algorithm edits. Preserve existing constructors/fixtures through a legacy constructor mode; distributed mode has a fixed boot binding and cannot use legacy admission to bypass final commit.

Move the existing registry into ReceiverState behind its common mutex. Keep `PayloadRegistry`, Entry, Slot and disk/proof fields opaque outside payload_owner. Permit only `pub(super)` access to concrete registry preparation/install/reap operations. PayloadOwners holds that same Arc, never a second admission mutex. Legacy mode needs no ReplayState; mini 3 adds a closed receiver-mode variant containing ReplayState for distributed mode. A missing replay state can never mean authorized distributed acceptance.

Split register_with into `prepare_entry`, `reserve_entry_locked`, `install_entry_locked` and `reap_locked`. First reserve a registry-owned preparation placeholder and bounded credit under the common lock. Allocate the empty memory Slot and bounded channels, then spawn its dormant supervisor outside the lock and publish the handle into that placeholder synchronously, with no intervening await, return to caller or user callback. The registry owns the handle before preparation can be abandoned. PreparedEntry is only a move-only ticket to this registered preparation, never the sole JoinHandle owner. Before spawning, a synchronous failure can roll back the empty placeholder through the common state; after spawning, every exit preserves registered ownership. The dormant task owns no disk and cannot submit work before activation. Dropping/refusing the ticket signals its existing gate to discard; the original placeholder retains the handle, credit and transferred transport charge until actual reaping and appears in snapshots throughout. Cancelled preparation or drain cannot take and drop the only handle. This is bounded setup, not an accepted final disk owner.

`PreparedEntry` and `EntryReservation` are opaque. The move-only EntryReservation is tied to the current mutable locked transaction and cannot escape it. reserve checks registry closure/failure, parent identity/kind/cancellation, parent lifetime, fixed free entry, ID room and required transport/quota lifetime ownership before replay. It tentatively reserves positions, counters and parent holds through that same mutable state. Rollback restores only those tentative changes before unlocking; its destructor never reacquires ReceiverState. Installation consumes the same reservation within that transaction, moves the registered handle and guards to their accepted positions, then activates the supervisor with a concrete message. It returns PayloadLease infallibly. Gate-send failure leaves a registered failed owner for reaping and cannot roll back replay. No spawn, parsing or fallible permit acquisition occurs in install.

For a route requiring both an account and a stream, reserve both positions and their parent relation before consume, then install both together. A dependency account closes only after its accepted uses finish and its own worker disposal/reaping completes; it cannot disappear when close merely becomes pending. Replace post-replay semaphore acquisition with transfer of the already owned transport guard and concrete local WorkKey/DependencyUse retention. Keep legacy semaphore guards in a closed internal guard enum for existing fixtures; do not expose an arbitrary user lifetime trait. A single transport exchange is charged once. Initial transport/prelude ownership transfers rather than acquiring the same role budget again. Operation and dependency payload roles remain separate from operation/partition capacity.

Bound payload registry entries by `1 + O + 4096 + 32`, for one process anchor, local operation accounts, at most one lazy dependency account per permit, and the 16 operation plus 16 dependency stream budgets. Dependency accounts share the configured process Spool and exact binding across attempts. They do not acquire an operation execution slot. Empty accounts initialize only on workers after install; reject a new account if no permit/entry room. Existing legacy fixtures may inject smaller bounds. No per-job process Spool or final anchor is created on refusal.

The separate 32 preparation placeholders have fixed nonborrowable shares: 24 data/boot and 8 control. A data exchange still needs its existing operation or job transport charge; preparation creates no extra transport capacity. An account-plus-stream preparation reserves both needed placeholders together and keeps one shared concrete transport owner, charged once and retained until all of its registered tasks reap. It refuses immediately if either preparation position is unavailable. The one boot process-anchor preparation uses one data/boot placeholder and the permanently reserved single process position before listeners activate; it requires the retained initialization identity, not a transport or compute charge. It cannot create a second process owner or retry around an unresolved first one. Its worker command creates the Spool and returns ProcessReady only through the retained entry.

Control preparation has a distinct typed path holding one already acquired control transport charge and one of its eight reserved placeholders. Its dormant memory-only task/handle transfers into the accepted-record table, not a payload disk slot. Control records consume neither operation/partition capacity nor data transport. A close response returns bounded Pending while prior owners survive; it never waits for dependency cleanup. Boot, data and control preparations use the same registered-placeholder, abandonment and reaping rules. All accepted control records fit within the O+P+64 bound below and retain their original transport charge through response delivery and reaping. Initial transport/prelude ownership transfers exactly once into a concrete retained owner; no second role charge is acquired. A saturated data/boot share cannot consume the eight control preparation positions.

Reaper updates capacity/dependency ownership by keys while holding ReceiverState, without guard Drop recursively locking it. Extract memory-only guard-release actions and notifications, unlock, then drop those guards/notify. If a release action can trigger another owner transition, retain a bounded pending-release count until that transition finishes under the receiver mutex; a snapshot cannot report idle in that gap. Never acquire receiver state while holding disk/slot handoff locks. The receiver may inspect short cancellation/status fields but never lock the disk cell. Worker commands retain disk-then-handoff ordering; no worker holds those locks while calling receiver methods. Parent child release must retain existing reaped-child-before-parent-disposal ordering.

Use existing WorkerPool/owner fixtures and actual command/return gates. Block Discard or the post-cleanup/pre-return gate: original transport and capacity must remain unavailable until handle reaping. Drop a buffered reply/observer and cancel an unpolled future; cleanup remains with the original supervisor. Refused reservation creates no scratch owner; repeatedly refused preparations cannot exceed credits and their dormant handles reap. Exercise process initialization before any transport exists, all 24 data/boot preparation positions, independent control preparation, and a cancelled control preparation with its original charge retained. Cancel a drain after cleanup completion but before supervisor termination/reaping, then resume it and assert the same registered handles, records and charges survive until observed termination. Premature pool stop retains failed entries/guards. Settle gates, owned tasks, anchors and pools before assertions; use existing quarantine teardown for deliberate failed-drain cases. Do not repeat the frame/Parquet codec matrix.

## Mini 3: A18 receiver transaction and focused lifetime composition

Depends on reviewed minis 1/2 AND reviewed R03a3b matching A18. Own only admission.rs final route methods and embedded private tests, narrow payload_owner.rs commit/lifetime wiring and private test hooks, and node/mod.rs reexports. No replay/verify/controller changes are preauthorized. If A18 lacks a required borrowed accessor, report that precise missing getter to its owner; do not expose proof fields or invent unchecked constructors.

Define an opaque admission-owned DurableRequestView. Its checked constructor consumes EligibleRequest and a borrow of the same validated Control outside the lock, computes the complete OwnershipObservation and requires equality with the proof's observation. From that root's exact Auth receiver it retains target node/incarnation/session/verifier, phase, registration and optional drain ID. The private retained eligible proof supplies the exact local boot/key association; no caller can supply these durable facts independently. This does not require new auth getters or recovering Node fields from an observation digest. No Clone, Serde, raw-parts or boolean constructor is exposed. No parsing, encoding or hashing occurs while applying this view.

Define concrete `ReceiverAdmission::accept(view, content, prepared_owner)`, a closed `AcceptedRequest` route enum and move-only `RequestObserver`. They are internal memory handoffs, not HTTP handlers or generic callbacks. Compare the view's complete observation and exact eligible local boot with current receiver state before applying permanent closure; a valid job or close can therefore be the first observation of durable draining. The view moves its original EligibleRequest into A18 consume. Existing borrowed accessors supply route, association, pending predicates and checked content identities without reparsing. Admission also owns the production StartCheck issuer: it accepts a fresh checked durable view for the retained WorkKey/request binding outside the lock, then next_start compares the complete observation, boot and current record/permit under the lock. It cannot issue a check from caller phase/ready flags.

The complete transaction under ReceiverState is: reap settled entries; observe the precomputed full root; reject superseded/inconsistent observation or wrong boot; apply permanent durable drain closure; compare current initialization and every route's PendingLocalChecks; reserve real work/dependency/payload positions and checked counters; call A18 consume; on replay/proof failure undo only tentative memory reservations; otherwise move into RequestHandoff and synchronously install the accepted owner and route transition. No await separates those steps. Root advancement/barrier closure may persist on refusal; sender sequence does not advance on capacity/permit failure. Replay is never rolled back after successful consume. Accepted operation/control tasks also require pre-registered dormant handles or a retained existing transport supervisor before consume; creating their lifetime task afterward would leave the same ownership gap as the old try_admit.

Operations install operation record, fresh admission_id, implicit self permit and owner together. Jobs install partition record plus exact existing DependencyUse. Open/close/drain/readiness reserve bounded control ownership and install their state/reply obligation under the same lock without compute slots. Delay open/close state mutation until consume succeeds, except conservative observation-driven barrier closure. Exact open retries use the same binding; closing/absent semantics remain mini 1's. Store the owned A18 body and original bytes, with its opaque binding, once in the accepted owner. RequestObserver loss does not release it. For operations, the registry retains the coordinator/publication handle through durable C02 resolution and cleanup; this mini provides retention/settlement methods and one owned gated task composition, not a coordinator or publication algorithm.

Receiver accepted records are bounded by O+P+64, apart from the 4096 permits and separately bounded payload entries. Transport guards bound validation/preparation and control records before those compute records exist. Keep A07's 64 total, 24 unclassified, 16 operation, 16 job, 8 control limits independent. No control handler waits for a dependency close, full compute pool or peer result. Later control parsing must use bounded independent CPU/I/O service so saturated partition/coordinator work cannot starve it; these minis add no listener budget implementation.

Expose `snapshot_locked() -> LocalSnapshot` with exact boot/barrier ID, initialization phase, four running/queued counts, open/closing dependency counts, validation/preparation/delivery/cleanup/accepted-supervisor counts, unresolved publication count, unreaped-handle count and failed-drain flag. Counts derive from retained records/handles. Process anchor existence alone is not active work; pending initialization/disposal is. `idle_candidate()` is internal and requires initialized exact boot, permanent exact drain barrier, all work/permit/supervisor/publication counts zero, all relevant handles reaped and no failure. It accepts no idle bool. Snapshot may feed occupancy to C03c but grants no provider or database authority.
