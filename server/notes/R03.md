## Interfaces for R04 and later tasks

All codec functions are synchronous. Future async callers should move owned inputs into `spawn_blocking` and await its result before publication.

- `snapshot::validate_rows(&TableDescriptor, &[Row]) -> Result<usize, ProtocolError>` validates the descriptor, complete exact-schema rows, exact scalar types, finite floats, unique utf8/int64 primary keys, at most 100000 rows and at most 64 MiB accounted payload. It returns the accounted byte count. Use on the complete proposed row set after mutations and before publishing. Invalid new rows return `validation_error`, duplicate keys return `conflict`, and limits return `limit_exceeded`.
- `snapshot::encode(&TableDescriptor, &[Row]) -> Result<Vec<u8>, ProtocolError>` validates before constructing Arrow arrays or writing Parquet. Columns follow BTreeMap name order. The writer closes before returning bytes, including for an empty table.
- `snapshot::decode(&TableDescriptor, bytes::Bytes, Option<u64>) -> Result<Vec<Row>, ProtocolError>` requires the expected descriptor. R04 should always supply `Some(entry.row_count)`. `None` leaves catalog count checking to the caller. A successful load establishes the R07 preconditions: every row is complete, nonnullable and schema-valid, all floats are finite, and primary keys are unique. Count mismatches, corrupt/truncated files, wrong schemas/physical types, nulls, nonfinite values and duplicate stored keys return `storage_unavailable`. Limits return `limit_exceeded`. All errors have `not_applied`; messages contain no row contents or raw dependency errors.
- `snapshot::MAX_ENCODED_SNAPSHOT_BYTES = 80 * 1024 * 1024`. Pass this exact limit to `Storage::read(&entry.snapshot_key()?, MAX_ENCODED_SNAPSHOT_BYTES)` before collecting bytes. Convert the returned Vec with `Bytes::from`, then decode. The decoder independently enforces this cap.

## Accounting and bounded loading

The deterministic logical payload is 8 bytes per row, plus 8 bytes and the UTF-8 column-name byte length per cell, plus the value size: UTF-8 byte length, 8 bytes for int64/float64, or 1 byte for bool. Names count in each row. This includes framing headroom and uses the same rule during validation and decoding. It measures logical payload, not allocator overhead or JSON escaping. The inclusive maximum is 64 MiB.

The private file profile uses flat REQUIRED fields, uncompressed PLAIN V1 data pages, no dictionaries or statistics, and one row group from the encoder. Disabling compression and dictionaries prevents page decompression and dictionary expansion before allocation. General Parquet import is outside scope; the decoder rejects other compression, dictionary pages, V2 pages and non-PLAIN values. Arrow metadata is ignored when inferring the schema, and physical types and required/nonrepeated levels are checked independently.

The 80 MiB encoded cap accommodates this encoder's <=64 MiB plain values plus 16 MiB for headers and metadata. String length prefixes consume less space than the per-cell accounting headroom; fixed-width values fit directly. Footer metadata is separately capped at 1 MiB before parsing. No compression codecs are enabled in the dependency. The pinned reader defaults page-statistic reading off, avoiding allocation of statistics byte strings from page headers.

Before Arrow allocates value arrays, decoding checks metadata counts, schema, physical types, column compression, column sizes/ranges and per-column counts. It scans pages as bounded slices of the capped encoded object. It checks each page count against the remaining row-group count, rejects dictionaries and unsupported page types/encodings, validates PLAIN string lengths and UTF-8 against the actual page buffer, verifies fixed-width lengths and float finiteness, and enforces cumulative accounted payload. A forged enormous string length fails before an Arrow string allocation. Uncompressed pages never allocate according to a claimed decompressed size. Arrow then reads batches of one row, with cumulative row/payload checks while constructing rows. Final validation checks uniqueness and repeats the complete row-set contract. Decoder dependency panics are mapped to a sanitized stored-data error.

## R03-F1 footer schema preflight

Changed only `src/snapshot.rs`, new private `src/snapshot/footer.rs`, `tests/snapshot.rs`, and this appended note. Public `validate_rows`, `encode`, `decode`, and `MAX_ENCODED_SNAPSHOT_BYTES` signatures and the trusted-row contract are unchanged. No Cargo, lib, storage, commit, protocol or plan edits.

`decode_inner` now obtains the actual footer slice from the existing envelope check, then calls `footer::validate` before `SerializedFileReader::new` and before `ParquetRecordBatchReaderBuilder::try_new_with_options`. The guard requires exactly `table.schema.len() + 1` schema elements, a group root with exactly the expected child count, and REQUIRED primitive children with no descendants. Zero child declarations on primitive children are harmless and accepted. Physical types are restricted to this codec's four types; the existing later schema checks still enforce exact names and expected types.

The private compact-Thrift scanner allocates no collections or strings. It borrows the already capped footer, bounds binary lengths and collection counts by actual remaining bytes, bounds maps by remaining key/value bytes, checks integer widths and ten-byte varint termination, and limits recursive skipping to depth 32. Every skipped collection item consumes input bytes. Ordered unique struct fields prevent duplicate schema declarations. Missing, truncated or invalid declarations return sanitized `storage_unavailable` with `not_applied`. Existing encoded/footer size caps and the new depth cap return `limit_exceeded`. Counts or lengths exceeding remaining bytes are malformed/truncated storage, not a claim that more input should be allocated.

This is the server-generated v0 profile, not general Parquet import. The scanner requires ordered unique fields, rejects unsupported compact types, and leaves full metadata/page semantics to the pinned reader and existing checks. Inspection used installed official parquet 60.1.0 sources in `file/metadata/thrift/mod.rs`, `schema/types.rs`, and `parquet_thrift.rs`; no cargo-cache changes or new library APIs.

Regression fixtures call the guard directly, before any library metadata loader. Modest root child counts 2 and 129 and a child declaring a descendant are rejected. Additional small fixtures check truncated/overstated binary/list declarations and the skip-depth cap. No allocation-bomb input was executed against Parquet. The regression failed against a temporary no-op guard using an isolated rustc harness while Cargo was locked by concurrent work. The new integration boundary checks both empty and populated 128-column snapshots; the prior five snapshot test groups remain in place.

Final focused verification passed: 2 footer guard unit tests and all 6 snapshot integration groups, including the prior 5 groups. Clippy passed for the library and snapshot test target.
