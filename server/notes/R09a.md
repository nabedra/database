# R09a: bounded response encoding

Implemented only `server/src/api/response.rs`, `server/tests/response.rs`, and this note. No module wiring, dependencies, engine/protocol changes, HTTP behavior, branches, commits, or pushes. Tests include the actual helper with `#[path]` and alias `meshdb_server::protocol` at the test crate root.

## Interface for R09 / R06

- `EncodedResponse { pub status: u16, pub body: Vec<u8> }` owns compact UTF-8 JSON bytes. It is a transport result, not another serialized response model.
- `encode_success<T: Serialize + ?Sized>(request_id: Uuid, data: &T, operation_is_mutation: bool) -> EncodedResponse` uses `SuccessResponse` with status 200. R06 can supply a typed result or `serde_json::Value` without changing this helper.
- `encode_error(request_id: Option<Uuid>, error: ProtocolError) -> EncodedResponse` uses `ErrorResponse` and `ErrorCode::status_code`. Pass `None` before a valid request UUID is known and `Some(id)` afterward.
- Internal `to_body` serializes directly into a bounded `Write` implementation. Each write checks remaining space before extending the buffer. The complete envelope may equal `MAX_BODY_BYTES`; overflow discards partial bytes and produces a 413 `limit_exceeded` envelope. An overflow flag also survives a custom serializer replacing a writer error.
- Other returned serialization errors produce a 500 `internal_error` envelope. Neither fallback contains user data or Serde diagnostics. Both fallback messages are fixed; their protocol-only envelopes are under 256 bytes and use the same bounded writer. The fallback encoding assertion depends only on these fixed strings and existing protocol derives, never on a user serializer.

Success encoding failures use `not_applied` for reads and `unknown` for mutations because execution may already have committed. Normal engine errors preserve the supplied outcome exactly. Oversized error messages also preserve that outcome in the 413 fallback. There is no retry, rollback claim, panic interception, logging, runtime, or network activity.
