# R08 handoff

Implemented only `src/executor.rs`, `tests/executor.rs` and this note. Library/API wiring remains for R09/R10. No dependency changes, secret reads, agents, worktrees, branches, commits or pushes.

## API

All types are in the future `crate::executor` module. Errors use `crate::protocol::{ProtocolError, ErrorCode, Outcome}`. There are no new dependencies.

```rust
Executor::new(workers: usize, queue: usize) -> Result<Executor, ProtocolError>
Executor::try_admit(&self) -> Result<Admission, ProtocolError>
Executor::stop_accepting(&self)
Executor::drain(&self) // async, returns ()
Admission::spawn<F, Fut, T>(self, work: F) -> Result<Operation<T>, ProtocolError>
Operation::receive(self) // async, returns Result<T, ProtocolError>
```

`Executor` is cloneable and all clones share state. `Admission` and `Operation` are owned, non-cloneable guards. `spawn` requires `F: FnOnce() -> Fut + Send + 'static`, `Fut: Future<Output = Result<T, ProtocolError>> + Send + 'static` and `T: Send + 'static`. No abort handle is exposed.

Constructor errors are `ValidationError/NotApplied` for zero workers, checked-add overflow or a total exceeding `Semaphore::MAX_PERMITS`. Queue uses usize. Admission is immediate, with exactly workers + queue total slots. Full/stopped admission returns `Overloaded/NotApplied`, ready for HTTP 429. An unused guard releases its slot on drop.

The admission count uses a private mutex; execution uses a separate Tokio semaphore. The detached task owns the admission guard and worker permit, and invokes the supplied closure only after acquiring the worker permit. Even future construction is deferred. Results preserve work errors. Tokio join panic/cancellation maps to `InternalError/Unknown`, without exposing panic payloads or retrying. Submitting outside Tokio returns `InternalError/NotApplied` and releases admission. Dropping `Operation`, or cancelling its `receive` future, drops only a join handle and does not abort the task. Panic unwinding and task cancellation release guards. Disconnected panics still run Tokio's panic hook, but their result cannot be delivered to a missing caller.

Stop and admission synchronize under the same mutex. Stop leaves the worker semaphore open. Previously issued guards can submit after stop; drain includes those guards as well as queued/running tasks. Drain also stops admission, supports concurrent waiters and can be cancelled and awaited again. It registers notification before checking the count to avoid missed completion notifications. A retained unused guard or work that never finishes intentionally prevents drain completion. No deadline or cancellation policy is added.

## R09 integration

Authenticate headers before admission. Then obtain an admission guard, move the unread request/body and owned engine references into `spawn(move || async move { ... })`, and read/limit/parse/validate the body inside that closure. Await engine execution and return the response result from the closure; await `operation.receive()` in the HTTP handler. Do not read or spawn body/engine work before passing the closure. A caller disconnect can discard `Operation` safely. An engine that already represents application failures in its response can return that response as `Ok(response)`.

R09 must declare the module in the library and translate executor errors through the normal protocol envelope. Authentication, body limits, routing, response serialization and HTTP disconnect detection remain outside this helper.

## R10 shutdown and engine responsibility

Call `executor.stop_accepting()` at shutdown, stop HTTP ingress, ensure any outstanding handler-held guards are submitted or dropped, then await `executor.drain()` before dropping the single Tokio runtime. Queued operations continue. There is no second runtime and no generic blocking scheduler.

The engine must await at most one `spawn_blocking` task at a time inside the detached operation. It must not start background computation that outlives the operation. Do not tear down or forcibly abort the runtime before drain; Tokio cannot stop an already running blocking closure on runtime cancellation. Global mutation locking belongs to the engine/R04.

The final explicit Tokio dependency features should include `macros`, `rt-multi-thread`, `sync`, and `time`. Executor production needs `sync` and runtime/task support; focused tests also use `time` for hang deadlines. These features currently arrive through the shared dependency graph. Cargo.toml and Cargo.lock were not edited.

## Validation

Tests were written first and the initial targeted test run failed because the executor module did not yet exist. After implementation, all four grouped actual Tokio tests pass. They cover queue zero, invalid/boundary configuration, unused guards, two active workers with four total admissions, deferred closure invocation, disconnected queued/running work, controlled awaited blocking work, concurrent drainers, preserved application errors and closure/future panics. Channels and semaphores control progress; timeout is only a hang-failure deadline.

Exact passing commands from repository root, with `/Users/antoniopenapena/.cargo/bin` on PATH:

```sh
cargo test --manifest-path server/Cargo.toml --test executor
cargo clippy --manifest-path server/Cargo.toml --test executor -- -D warnings
rustfmt --edition 2024 --check server/src/executor.rs server/tests/executor.rs
```
