# R09b health routing

Implemented only `server/src/api/health.rs`, additive `pub mod health` in
`server/src/api.rs`, `server/tests/health.rs`, and this note. No dependency,
bootstrap, engine, storage, executor, or operations endpoint changes. No secrets,
real AWS, agents, worktrees, branches, commits, or pushes.

## Interface for R10

```rust
pub fn api::health::router<B: ObjectStore + 'static>(engine: Engine<B>) -> axum::Router
```

The constructor returns `Router<()>` with private supplied state and performs no
I/O. Pass a clone of the same initialized Engine used by operations. For example:

```rust
let app = api::router(engine.clone(), executor.clone(), token)
    .merge(api::health::router(engine.clone()));
```

Both routes are unauthenticated with empty response bodies. Liveness returns 200
without storage access. Readiness performs exactly one fresh
`engine.storage().load_catalog()` inside a five-second Tokio timeout. Storage
enforces its catalog byte bound and validates the supported catalog format.
Success returns 200; every storage/validation failure or timeout returns 503.
The timeout covers the complete load, including adapter read retries and body
consumption. It drops the pending load on expiration. Health adds no retry,
initialization, PUT, listing, mutation lock, admission permit, coordinator, or
runtime. The private `ready` handler returns only a status and logs nothing.
