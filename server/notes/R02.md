# R02 storage and catalogs

Implemented only bounded S3 object access and catalog load/initialization. Files: `src/storage.rs`, the storage export in `src/lib.rs`, `Cargo.toml`, `Cargo.lock`, `tests/storage.rs`, `tests/support/storage.rs`, and this note. No protocol, engine, executor, transport, CLI or plan edits. No AWS requests, .env reads, delegation, branches, worktrees, commits or pushes.

## Interfaces for R03/R04

- `Storage<B: ObjectStore>` is the application entry point. `Storage::new(backend, Namespace)` supports fakes. `Storage::<S3Store>::connect(bucket, Namespace).await` loads the standard AWS credential and region chains, rejects missing/invalid bucket or region, and binds a single existing bucket. It does not provision or probe a bucket. A subsequent catalog read surfaces denied/missing credentials or an inaccessible bucket. The SDK adapter also checks its bound namespace on every call.
- `Namespace::new(prefix)` normalizes trailing slashes to one and rejects empty, absolute, URL-like, traversal, empty internal path components and unsafe escaped paths. The future CLI supplies `MESHDB_S3_BUCKET` and defaults `MESHDB_S3_PREFIX` to `meshdb-v0/`. The standard SDK chain handles AWS_REGION, environment credentials, profiles and roles. No dotenv loader is present.
- `ObjectKey::catalog()`, `ObjectKey::snapshot(table_id, commit_id)`, `ObjectKey::parse_snapshot(path, table_id)` and `as_str()` represent only catalog or canonical relative snapshot paths. Snapshot commit UUIDs need not equal the latest catalog commit UUID because unchanged tables retain earlier snapshots.
- `read(&ObjectKey, max_bytes).await` returns `Object { bytes, etag }`. It consumes ByteStream frames and rejects overflow before adding a frame to the accumulated buffer. ETags are opaque strings, including quotes. `put(key, Vec<u8>, WriteCondition::Create | Match(&etag)).await` returns the new opaque ETag. Create sends If-None-Match: *. Match sends If-Match and is accepted only for the catalog. There is no unconditional write, listing, deletion, bucket management or arbitrary per-call bucket.
- `ObjectStore` is the trusted Send + Sync backend adapter contract with Send asynchronous get/put futures. `Download` carries ByteStream and an opaque ETag. `backend()` permits test failure controls. Production callers should use Storage. AWS conditional PUTs use a separate client with `RetryConfig::disabled()`; reads retain ordinary SDK behavior. The credential chain may use role/SSO providers, but application object operations use only S3.
- `StorageError` is sanitized and contains no raw SDK error or configuration value. NotFound is a definite GET 404, excluding an explicit NoSuchBucket service error. Conflict means definite PUT 409/412. Other 4xx write failures are Unavailable; network/lost responses, 5xx and a successful PUT missing its ETag are Ambiguous. R04 must reconcile Ambiguous, never replay automatically. Read failures are Unavailable except definite NotFound and byte overflow. Configuration, InvalidPath, InvalidCatalog, UnsupportedCatalog and LimitExceeded are separate errors. No client mutation outcome is assigned at this layer.
- `load_catalog().await` always performs a fresh bounded GET and returns `LoadedCatalog { catalog, etag }`. `initialize_catalog().await` returns valid existing metadata unchanged. Only NotFound attempts Create. Conflict or an ambiguous initialization response causes one fresh validated read; any other error fails startup. No retry loop or unconditional overwrite occurs.
- `Catalog { format_version, revision, commit_id, tables }`, `CatalogEntry { id, schema, key, format, snapshot, row_count }`, `Catalog::empty()`, `validate()`, `decode(bytes)`, `encode()` and `CatalogEntry::descriptor(name)`/`snapshot_key()` are public for later tasks. `decode` is the authoritative byte decoding path; direct Serde decoding alone does not validate the document. It checks object shapes, unknown/duplicate fields and names, protocol schema/key/name rules, supported version 1, UUIDs, distinct table IDs, parquet format, row count <= 100000 and canonical table-matching snapshot paths. Decode and encode enforce 1 MiB; encode uses a bounded writer. Initial revision 0 uses UUID `6e894cb9-9b3b-47e5-a964-581df72d7e14` and an empty table map. R04 owns revision increments and commit UUID generation.
- `tests/support/storage.rs` provides reusable `Fake` and mutex-protected `State` with real ETag generation/comparison and object bytes. Controls include denied reads/writes, an initializer race winner and loss of a successful PUT response. Fake GETs deliver eight-byte frames with unknown total length to exercise download limits. Later integration tests can include this support file using `#[path = "support/storage.rs"]`.

## Outside R02

R03 owns Parquet serialization, snapshot row/decoded-payload validation and bounded snapshot loading policy. R04 owns mutation locking, catalog revision/UUID updates, snapshot publication order, ambiguous mutation reconciliation and ProtocolError/outcome mapping. Caller timeouts, readiness/startup wiring, environment/CLI parsing, HTTP(S), operation execution and real S3 acceptance remain later tasks. There is no claim of a successful client mutation from initialization. No garbage collection or recovery by listing is implemented.
