# R06a handoff

Implemented only `server/src/engine/mutation.rs` and its source-path integration
test `server/tests/mutation.rs`. No module wiring or dependency changes.

The public API is synchronous:

```rust
apply(&TableDescriptor, &Operation, Vec<Row>) -> Result<Mutation, ProtocolError>
```

`Mutation` exposes `rows: Vec<Row>`, `result: MutationResult`, and `changed: bool`.
Serialize `result` as response data. Its untagged variants are `Null` for
insert/upsert, `Count(usize)` for insert_many, and `Found(bool)` for update/delete.
The bool indicates existence independently of `changed`. Empty batches, missing
keys, empty updates, identical updates and identical upserts return no change.
Float comparison uses bits, so replacing a signed zero preserves its sign and
reports a change. Existing row order survives; additions append in request order.

Descriptor and operation validation use the protocol validators before lookup or
mutation. Duplicate inserts/batches return conflict, malformed inputs return
validation errors, and batch/result row excess returns limit errors. Other valid
operations return unsupported_operation. All errors carry not_applied and return
no candidate rows or successful prefix. Lookup uses scans; batch duplicate checks
use a temporary typed key set. Private helpers are not integration contracts.

The loader must supply complete, exact-schema rows with finite floats, unique
keys and valid table row/payload limits. This module trusts those snapshot
preconditions, rather than repeating loader validation. It enforces the 100,000
resulting-row limit and delegates the 10,000 request-row limit to protocol.

The next engine task must wire the module and resolve catalog IDs, serialize
writes against the current snapshot, and retain committed state on errors.
Before publishing any changed candidate, call the R03 helper to validate the
64 MiB decoded payload limit and encode Parquet, then use R04 publication.
Only install candidate rows after successful publication; publication failures
and uncertain outcomes belong to that integration. A successful pure apply is
not a durable commit. No-change results can skip encoding/publication. Query/get,
catalog lifecycle, storage, concurrency, and durable atomicity remain outside
R06a.
