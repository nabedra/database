## Interfaces for later tasks

Import `meshdb_server::protocol::*`.

- `parse_request(&[u8]) -> Result<Request, ProtocolError>` is the authoritative request entry point. It checks the 8 MiB request limit, required UUID envelope, strict payloads, operation classification and schema-independent validation. Unknown operation names return `UnsupportedOperation`; malformed supported requests return `ValidationError`. Direct `Request` Serde deserialization also validates but reports Serde errors without structured error codes and does not enforce byte size.
- `Request { request_id: Uuid, operation: Operation }` serializes the exact `request_id`/`operation`/`payload` envelope. `Operation` has all 13 explicit variants and payload structs. `Operation::validate()` supports requests constructed in Rust.
- Resolve the immutable ID through the catalog, then call `operation.validate_for_table(&TableDescriptor)`. It checks descriptor/ID agreement, complete insert/upsert/batch rows, partial updates without the key, key types and query columns/types. Catalog lookup and `not_found` remain engine responsibilities. Create/describe/list need no resolved descriptor; their independent validation runs during parsing.
- `TableDescriptor`, `Schema`, `ColumnType`, `TableFormat`, `Row`, `Scalar`, `Key`, `Query`, `OrderBy`, `Predicate`, `Comparison`, `ComparisonOp`, `LogicalPredicate` are public wire types. `validate_identifier`, `validate_schema`, `validate_scalar`, `validate_row` with `RowMode` and query/predicate validation can also be reused during catalog/snapshot decoding. Validate descriptors before standalone row validation. Scalars preserve integer versus float syntax and reject null, objects, arrays, out-of-range integers and nonfinite floats. The arbitrary_precision JSON feature prevents overflowing integers from silently becoming floats.
- All four query fields are required, explicit null is accepted, and objects cannot use positional arrays on the request path. Predicate root depth is one; maximum is 32 including leaves. Code-shaped values are rejected; strings remain literal data. Query limits are nonnegative u64 values; limits above 10000 are valid because execution enforces actual result counts.
- `ErrorCode::status_code()`, `ProtocolError::new(code, message, outcome)`, `Outcome`, `SuccessResponse<T>` and `ErrorResponse` support later HTTP responses. Validation errors are `NotApplied`. Later mutation layers must explicitly supply `Unknown` when commitment is uncertain. Error responses support a null request ID before a valid ID is available; request ID extraction for failures belongs to transport.
- Public constants cover body/catalog bytes, batch/result/table rows, decoded payload bytes, schema columns and predicate depth. Only request body size, batch count, schema size and predicate depth are enforced here.

## R01-F1 strict deserialization follow-up

Changed only `server/src/protocol.rs`, `server/tests/protocol.rs` and this note. No dependency metadata changes.

`Scalar` now captures raw JSON and rejects object/array/null syntax before converting primitive values. Both `$serde_json::private::Number` and `$serde_json::private::RawValue` object attacks fail in direct scalar decoding, rows and comparison values. Integer syntax still requires i64 bounds; decimal/exponent syntax produces finite float64 values. `ColumnType`, `TableFormat` and `ComparisonOp` deserialize strings only; their serialized spellings are unchanged.

Predicate decoding dispatches on a string `op` with strict per-variant fields and raw child values. This avoids Serde's untagged/internal-tagged content buffers, which cannot preserve the raw scalar boundary. Recursive decoding enforces depth 32 before descending further. Direct `LogicalPredicate` decoding uses the same path. Direct `Operation` decoding also preserves raw payloads when the payload appears before its operation tag. The adjacent operation/request tags already require strings; `Key`'s string/i64 alternatives do not accept marker objects. Response-only `ErrorCode` and `Outcome` were outside the request fix.

Public names, fields, variants and function signatures are unchanged. `parse_request` remains authoritative, including structured errors and request size checks; `validate_for_table` remains required after catalog resolution. Direct `Operation` decoding still requires a separate `validate()` call. Scalar/predicate/operation deserialization now requires JSON raw-value support, including direct serde_json deserializers and serde_json::Value. Arbitrary third-party Serde content buffers are not supported. A Value that upstream code already parsed with marker interpretation cannot recover the original object syntax; use `parse_request` on original request bytes.

Two grouped regressions were added and observed failing before the fixes: marker object conversion and object-form schema enums. A payload-before-operation regression also failed before the related buffering fix. Six integration tests now pass. The scalar matrix checks direct Scalar, Request and Operation decoding, authoritative rows and nested and/or/not comparisons, exact decoded types/values, i64 endpoints, decimal/exponent floats, overflow, nonfinite values and forbidden shapes. Enum cases check intended string serialization/deserialization and object rejection. Existing strict-field/operator and depth boundary cases also pass.
