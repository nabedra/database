# R06 integrated row mutations

Implemented only `src/engine/write.rs`, `tests/engine_write.rs`, and this note.
No engine/lib/Cargo/dispatch wiring, peer edits, agents, branches, commits or pushes.

## Interface and execution

The inherent method is:

```rust
Engine<B: ObjectStore>::mutate(&self, Operation)
    -> impl Future<Output = Result<mutation::MutationResult, ProtocolError>>
```

It accepts exactly Insert, InsertMany, Update, Upsert and Delete. All other
variants return unsupported_operation/not_applied without storage access.
Results retain R06a's serializable untagged Null, Count(usize), Found(bool)
semantics. Found reports existence even for an unchanged row.

The method begins the shared coordinator session before catalog loading, resolves
only the immutable table UUID, and validates the operation on an awaited blocking
worker before snapshot access. It consumes the existing R07a helpers unchanged:

```rust
read::resolve_table(&Catalog, Uuid)
    -> Result<(TableDescriptor, CatalogEntry), ProtocolError>
read::load_rows<B: ObjectStore>(&Storage<B>, TableDescriptor, CatalogEntry)
    -> impl Future<Output = Result<Vec<Row>, ProtocolError>>
```

The loader bounds the download and awaits blocking decode. The next blocking
worker applies `mutation::apply` and, only for changes, calls `snapshot::encode`.
That encoder validates the complete schema, typed key uniqueness, row count and
64 MiB payload before building closed Parquet bytes. There is at most one
blocking job outstanding. The session remains in scope throughout these awaits.
Only the resolved entry's row_count and canonical snapshot path change before
`session.publish(candidate, Some(bytes))`. Success follows confirmed publication;
unknown publication outcomes propagate unchanged. Prepublication and join errors
remain not_applied, with sanitized internal_error for a failed blocking join.
No-change results skip encoding and all PUTs. There is no state cache or retry.

As with R05/R07a, the executor must retain and await admitted mutation futures
through completion across disconnects, including their blocking jobs. This
method adds no runtime, detached operation, cancellation policy or timeout.
