# R09 operations HTTP integration

Implemented only `src/api.rs`, additive `src/lib.rs` api/executor exports,
`Cargo.toml`, `Cargo.lock`, `tests/api.rs`, and this note. Existing response,
executor, protocol, engine, and storage implementations are unchanged. No agents,
worktrees, branches, commits, pushes, real AWS, or environment-secret reads.

## R10 contract

```rust
pub fn api::router<B: ObjectStore + 'static>(
    engine: Engine<B>, executor: Executor, token: String,
) -> axum::Router
```

The engine must already have initialized storage. Construct ONE Engine and ONE
Executor, pass clones to this constructor, and retain their shared handles for
health checks and shutdown. The constructor performs no I/O and creates no runtime
or listener. It returns a `Router<()>` with private supplied state and only
`POST /v1/operations`. Merge it with a separately supplied health router. Stop
admission and ingress, then await the retained executor's drain before runtime
shutdown. Existing public `executor` and `api::response` APIs are now exported.

State holds the initialized engine, shared executor and caller-validated token.
It has no Debug implementation. R10 should install its tracing subscriber;
this task emits completion events but installs no process-global subscriber.

## Request and result behavior

Authentication examines headers before immediate admission. Missing/wrong bearer
credentials and duplicate Authorization fields return 401 unauthorized/not_applied
with a null ID. Full/stopped executors return 429 overloaded/not_applied with a
null ID. Neither path polls the body. Scheme matching is case insensitive; the
credential must exactly match the configured nonempty token.

Only the executor-owned closure constructs body processing, after the worker
permit is held. It parses one Content-Type header using mime and accepts
application/json with ordinary parameters. Missing, malformed, duplicate or
incompatible Content-Type returns the existing 400 validation_error/not_applied
with a null ID. No new protocol code or 415 status is introduced.

The frame loop bounds actual data to an inclusive 8 MiB, independent of declared
Content-Length, and never appends a frame that would exceed the bound. Oversize
returns 413 limit_exceeded; unreadable bodies return sanitized 400 validation_error.
These errors have null IDs because no complete validated JSON body is available.

Original bytes go directly to protocol::parse_request. A separate minimal visitor
recovers correlation IDs from complete JSON objects with unique top-level fields
and a UUID string. It ignores other values without constructing a Value tree.
Invalid/missing IDs, nonstring IDs, duplicate top-level fields, malformed JSON and
trailing content produce null IDs. A valid ID survives payload/schema errors,
unknown operation names and unknown envelope fields. Nested payload duplicates
are rejected by the authoritative protocol parser; an otherwise valid top-level
ID remains available for that error. The scan never authorizes engine dispatch.

Engine::execute is called exactly once for each valid request, without retry.
Typed ExecuteResult goes directly to encode_success with Operation::is_mutation;
errors go through encode_error without changing their code/status/message/outcome.
Actual transport responses contain those bounded bytes and application/json.
Parsing and encoding remain synchronous inside tracked work; no additional
blocking jobs or untracked CPU work are spawned here.

Dropping a handler/result only detaches the executor operation. Both permits stay
owned through execution, response encoding/construction, and completion logging.
Receive failures preserve the executor's conservative unknown outcome and use a
null ID because the handler has no safely recovered correlation metadata.

Completion events contain only safe UUID/None, static parsed operation name/None,
elapsed milliseconds, error code and HTTP status. No request bytes, arbitrary
operation strings, rows, error messages, headers, tokens, or configuration are
logged. Encoding fallback status is reflected in the logged error code. Normal
completion events run inside tracked work, so disconnects do not remove them.
Pre-admission rejections and executor receive failures log in the handler.

## Dependencies and checks

Pinned stable Axum 0.8.9 with only http1/tokio features, http-body-util 0.1.5,
mime 0.3.18, tracing 0.1.44, and development tower 0.5.3/util. Tokio explicitly
retains macros, rt-multi-thread, sync and time. Official documentation checked:
[Axum](https://docs.rs/axum/0.8.9/axum/),
[frame polling](https://docs.rs/http-body-util/0.1.5/http_body_util/trait.BodyExt.html),
[MIME parsing](https://docs.rs/mime/0.3.18/mime/),
[tracing](https://docs.rs/tracing/0.1.44/tracing/), and
[Tower ServiceExt](https://docs.rs/tower/0.5.3/tower/util/trait.ServiceExt.html).

Four grouped router tests use the existing conditional Fake and real Engine,
without networking. They cover envelopes, full parser error preservation,
unsupported operations, schema and engine errors, strict IDs/duplicate fields,
content types, exact body limit and one-byte overflow with misleading length,
unreadable frames, unpolled unauthorized/overloaded/queued bodies, and cancelled
mutation completion with retained admission/drain. Gates and direct future polling
control synchronization; no sleeps. Existing response/executor coverage is reused.
The initial focused run failed on missing api/executor exports, then passed.
