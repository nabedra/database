# R04 mutation publication

Implemented `src/commit.rs`, the additive `lib.rs` export, `tests/commit.rs`, and backward-compatible conditional fake controls in `tests/support/storage.rs`. Cargo enables UUID v4 and Tokio sync explicitly; the lockfile records UUID's random dependency. No protocol, snapshot, engine, executor, routing, CLI or implementation-plan edits. No AWS calls, credential/.env reads, delegation, branches, worktrees, commits or pushes.

## Interface for R05/R06

Construct one `Arc<Coordinator<B: ObjectStore>>` from initialized `Storage<B>` per engine. Coordinator deliberately has no Clone implementation; clone the Arc. `storage()` permits ordinary unlocked reads. All mutations must use the session API rather than direct storage PUTs.

`begin().await -> Result<MutationSession<'_, B>, ProtocolError>` acquires the global Tokio mutex before a fresh validated catalog load. The session retains that lock through caller snapshot reads, validation, encoding, upload, publication and reconciliation. `catalog() -> &Catalog` exposes the immutable loaded state. `commit_id() -> Uuid` is a server-generated v4 UUID. `candidate() -> Catalog` returns a detached clone with checked revision + 1 and that UUID. Revision exhaustion fails admission without PUTs.

`publish(self, candidate: Catalog, snapshot: Option<Vec<u8>>).await -> Result<LoadedCatalog, ProtocolError>` consumes the session. Change exactly one named table. Create/data changes require one nonempty snapshot and reference `ObjectKey::snapshot(entry.id, session.commit_id())`. Existing table ID/schema/key/format cannot change. Drop requires None. Header tampering, no-op publication, multiple changed tables, wrong references, and mismatched snapshot presence fail safely before PUT. No-ops should drop the session and return the engine's appropriate result.

Preconditions: R05/R06 supply fully validated, closed encoded Parquet bytes matching the candidate schema and row_count. Empty table creation supplies valid empty Parquet. R04 accepts no raw rows, does not decode snapshots and does not depend on codec implementation. Its documented `MAX_ENCODED_SNAPSHOT_BYTES` is the same 80 MiB bound as R03. The coordinator enforces that bound and authoritative Catalog::encode validation/1 MiB serialization before any PUT.

Snapshot PUT uses Create, then catalog PUT uses Match with the original opaque ETag. The loaded catalog is never mutated in place. Success returns published metadata and ETag. Old snapshots and orphans remain. There is no listing, deletion, replay, or publication retry.

## Outcomes

- Candidate validation failures return validation_error/not_applied. Size/revision limits return limit_exceeded/not_applied.
- Snapshot conflicts return conflict/not_applied; every other snapshot upload failure returns storage_unavailable/not_applied, including ambiguous uploads. Catalog publication never follows a failed snapshot upload.
- Definite catalog conflicts return conflict/not_applied. Other definitive failures return sanitized not_applied errors, normally storage_unavailable.
- Ambiguous catalog PUT triggers exactly one fresh validated catalog load while retaining the lock. Matching commit UUID proves success and returns the observed LoadedCatalog. A different UUID, an older catalog, malformed metadata or any read failure returns outcome_unknown/unknown. Timeout does not prove rollback.
- Admission storage errors are sanitized and not_applied. No raw SDK errors, keys, credentials or body diagnostics appear in ProtocolError.

## Verification

Payloads are opaque stand-ins at this layer; codec tests own Parquet validity. Fake conditions remain real; targeted faults and semaphore read gates require no sleeps or AWS.

All defaults preserve existing fake behavior.
