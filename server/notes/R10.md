## Bootstrap and interfaces

The executable is `server/target/debug/meshdb-server`, absolute path
`/Users/antoniopenapena/Documents/ResearchProjects/AI/meshdb/server/target/debug/meshdb-server`.
It accepts the existing `Cli` / `Command::Serve(ServeOptions)` contract.
The private `main::run(ServeOptions) -> Result<(), &'static str>` validates config,
parses TLS, registers signals, connects storage using the standard AWS chain,
calls `initialize_catalog` exactly once, constructs one Engine and Executor,
then binds and serves. Storage/catalog failures terminate startup without reset.
All bootstrap error messages are fixed strings without configuration, paths,
SDK errors or key material. Clap retains normal help/version behavior.

The sole new library interface is:

```rust
pub async fn runtime::serve<B: ObjectStore + 'static>(
    listener: tokio::net::TcpListener,
    engine: Engine<B>,
    executor: Executor,
    token: String,
    tls: Option<axum_server::tls_rustls::RustlsConfig>,
    shutdown: impl Future<Output = std::io::Result<()>>,
) -> std::io::Result<()>
```

The caller supplies an initialized engine, shared executor, validated token and
already bound nonblocking listener. `None` selects HTTP; `Some` selects native
HTTPS. The function merges operations and health routers using the same engine.
Keep its future alive until it returns; external cancellation skips drain.
No framework or additional runtime is introduced.

## Runtime choices

`#[tokio::main]` supplies the sole runtime. CLI workers govern Executor admission
and execution, independently of runtime thread or process counts. Tokio explicitly
retains macros/rt-multi-thread/sync/time and adds net/signal/io-util.

Pinned stable axum-server 0.9.1 enables `tls-rustls`; Rustls 0.23.46 explicitly
installs AWS-LC before PEM parsing, avoiding ambiguous provider selection when
ring is also present transitively. `RustlsConfig::from_pem_file` parses the
certificate and private key and invokes Rustls `with_single_cert`, including key
consistency validation, before S3 connection or listener binding. Native TLS
supports TLS 1.2/1.3. No TLS reload or client certificate requirement is added.

SIGINT/SIGTERM stop executor admission and call `Handle::graceful_shutdown(None)`.
Connections finish, then Executor drain waits for every admitted operation,
including detached operations and their awaited blocking jobs. No mutation
cancellation or shutdown deadline is added. A stalled admitted operation can
therefore delay exit indefinitely, by contract. Bind failure explicitly drains
before returning. Socket accept errors are forwarded through a bounded channel
into the same graceful shutdown path and return a sanitized error after drain;
individual client/TLS handshake errors do not stop the listener. Ordinary signal
shutdown returns success/exit 0. Windows uses Tokio Ctrl+C.

A minimal tracing subscriber enables only the MeshDB API target at INFO. It
ignores ambient RUST_LOG and excludes SDK/HTTP diagnostics. Existing safe request
completion events are emitted to stderr; bootstrap never prints config or tokens.

API choices checked against official [axum-server documentation](https://docs.rs/axum-server/0.9.1/axum_server/)
and its downloaded pinned sources, plus installed Rustls source
`server/builder.rs` and `crypto/signer.rs` for certificate/key validation.

## Validation

Tests were added before implementation. Initial runs failed because Cargo had
no binary target and the runtime module was absent. The focused passing test
serves real HTTP liveness, gates detached fake-engine catalog work, verifies
admission and ingress stop, then verifies shutdown waits until that work completes.
The process test runs actual help/serve-help/version and rejects missing required
config, zero workers, an incomplete TLS pair and malformed PEM. All child
environments are cleared and contain only synthetic MeshDB settings.

Commands are run sequentially for Cargo, from the repository root:

```sh
export PATH=/Users/antoniopenapena/.cargo/bin:$PATH
export CARGO_BUILD_JOBS=2
export CARGO_PROFILE_DEV_DEBUG=0
export CARGO_PROFILE_TEST_DEBUG=0
cargo test --manifest-path server/Cargo.toml --test startup --test runtime
cargo build --manifest-path server/Cargo.toml --bin meshdb-server
cargo fmt --manifest-path server/Cargo.toml --check
cargo clippy --manifest-path server/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path server/Cargo.toml
```

Results: both focused tests passed; explicit binary build, full formatting and
all-target Clippy with warnings denied passed. The full Rust suite passed all
70 tests, with empty binary and doc-test targets also successful. The final
binary was explicitly rebuilt after validation. About 953 MiB remained free.

Disk space was checked before compilation. Only generated target incremental
artifacts and obsolete integration-test executables were removed, with no Cargo
build active during cleanup. Build profiles were unchanged.
