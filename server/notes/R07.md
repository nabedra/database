## Integration API

Future `src/engine.rs` can declare `pub mod query;` or `mod query;` and call:

```rust
pub fn collect(table: &TableDescriptor, query: &Query, rows: &[Row]) -> Result<Vec<Row>, ProtocolError>;
pub fn count(table: &TableDescriptor, query: &Query, rows: &[Row]) -> Result<u64, ProtocolError>;
pub fn explain(table: &TableDescriptor, query: &Query) -> Result<String, ProtocolError>;
```

All types come from `crate::protocol`. These functions have no async, store, callback or runtime dependencies and can execute inside a future `spawn_blocking` closure. Until engine wiring exists, the integration test aliases `meshdb_server::protocol` at its crate root and includes the actual evaluator by path. There is no alternate test implementation. Helpers remain private.

Every entry validates `table.validate()` followed by `query.validate(&table.schema)`. The caller resolves table IDs and must check operation/descriptor ID agreement through protocol validation. The snapshot loader must supply complete schema-valid rows, finite floats and unique primary keys, and enforce table row/payload limits. The evaluator deliberately does not repeat table validation per row. Its internal indexing/comparison assertions rely on that loader precondition; invalid public descriptor/query values fail through protocol errors before row access.

Collect applies filter, order, limit, projection. Default order is primary-key ascending; explicit ascending/descending orders always break ties by primary-key ascending. Float comparisons are numeric, so both zero signs tie. Projection can omit filter/sort columns. A limit exceeding usize or the row count has no effective reduction. Result counts above 10,000 return `LimitExceeded`, never implicit truncation.

Count scans borrowed rows and stops at the query limit without sorting, projecting or allocating a row response. It accepts counts exceeding 10,000. Explain accepts metadata/query only and prints scan, filter JSON, sort/tie-breaker, limit and projection, so no row scan is possible.

Collect checks the serialized projected JSON array against 8 MiB with a bounded byte-counting writer, including JSON escaping. Explain checks its serialized string against the same budget. These checks do not allocate another result-sized byte buffer. They return `LimitExceeded` with `NotApplied`; unexpected serialization failures return `InternalError`. R09 must still serialize and bound the complete success envelope, including request ID/wrapper overhead. Count's u64 result cannot approach that body limit.
