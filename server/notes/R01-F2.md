Implemented only `server/src/protocol.rs`, `server/tests/protocol.rs`, and this note. Inspected the existing raw scalar/object deserializers and required nullable helper before editing.

`Query.limit` remains a required `Option<u64>` field. Its private `required_nullable_limit` deserializer checks raw JSON syntax, accepts null and unsigned decimal integer tokens, preserves every u64 exactly, and saturates larger integers to `u64::MAX` with bounded arithmetic. Negative tokens, including -0, decimals, exponents, booleans, strings, objects, arrays, and Serde private Number/RawValue marker objects fail validation. Existing unknown-field rejection, request body bounds, and scalar int64 typing remain intact.

The pure evaluator contract needs no changes. With at most 100,000 table rows, both an overflowing positive limit and `u64::MAX` exceed every possible matching row count. Saturation therefore changes neither collect/count results nor result-limit errors. Null still means no explicit limit; zero still selects zero rows. Serialization and explain text use the normalized u64 value for overflowing inputs, rather than reproducing their original digits.

One grouped regression exercises raw requests through `parse_request` for collect/count/explain. It covers ordinary bounds, u64 maximum and maximum plus one, a 4,096-digit integer, null/zero, invalid syntax/types, and both marker-object bypasses. Existing protocol groups cover missing limit and unknown query fields.
