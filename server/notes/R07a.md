# R07a read-side engine integration

Implemented only `src/engine/read.rs`, `tests/engine_read.rs`, and this note. Parent module declarations and the implementation plan remain with the orchestrator. No dependency or peer-file edits, secrets, AWS, agents, worktrees, branches, commits or pushes.

The inherent async Engine methods accept owned protocol payloads and return:

- `get(&self, KeyPayload) -> Result<Option<Row>, ProtocolError>`
- `collect(&self, QueryPayload) -> Result<Vec<Row>, ProtocolError>`
- `count(&self, QueryPayload) -> Result<u64, ProtocolError>`
- `explain(&self, QueryPayload) -> Result<String, ProtocolError>`

Each call loads exactly one fresh catalog without a mutation lock, resolves only the immutable UUID, and awaits blocking protocol context validation before snapshot access. The three query methods share the protocol's identical collect/count/explain validation rules. Get scans for an exact typed key and returns None for an absent row. Collect/count/explain retain R07 semantics and array/string limits. Explain uses metadata only, with no snapshot GET or decode.

Fixed reusable interfaces in `engine::read`, unchanged from the task specification:

```rust
pub(super) fn resolve_table(catalog: &Catalog, id: Uuid)
    -> Result<(TableDescriptor, CatalogEntry), ProtocolError>;
pub(super) async fn load_rows<B: ObjectStore>(storage: &Storage<B>, table: TableDescriptor, entry: CatalogEntry)
    -> Result<Vec<Row>, ProtocolError>;
```

Resolve requires a validated catalog. Load requires its matching descriptor/entry. Load reads exactly `entry.snapshot_key()` through `Storage::read` with `snapshot::MAX_ENCODED_SNAPSHOT_BYTES`, which bounds bytes before buffering. It then awaits `spawn_blocking` for `snapshot::decode(&table, Bytes::from(object.bytes), Some(entry.row_count))`. The codec returns complete validated owned rows. Key scans and pure query execution run in subsequent blocking tasks. Each operation awaits at most one blocking task at a time; there is no new runtime, detached work, retry, cache or lock. Missing references, unavailable storage and corruption return sanitized storage_unavailable/not_applied; limits retain limit_exceeded. Blocking join failures return sanitized internal_error/not_applied.

Three integration groups compile the actual engine.rs, read.rs and query.rs using crate aliases and `#[path]`. They use the shared conditional fake and R04 publication with actual Parquet snapshots. Tests cover mixed scalar get, missing keys, composed query/count/explain, fresh reads after publication, key type and query column rejection before snapshot access, metadata-only explain with missing data, missing/corrupt/unavailable failures, and stale UUID rejection. A local snapshot-only semaphore gate proves a captured read completes across update, drop and name reuse without another catalog or snapshot GET. No sleeps or AWS. The initial test-first run failed because read.rs was absent; a test-only Query constructor error was corrected before the passing run.
