# R10a: synchronous startup configuration

Implemented only `server/src/config.rs` and `server/tests/config.rs`, with this handoff note. No library exports, dependencies, CLI, runtime, transport, storage initialization, or plan edits.

## Contracts for R10

- `ServeOptions` has public typed fields `host: IpAddr`, `port: u16`, `workers: usize`, `queue_size: usize`, and `tls_cert`/`tls_key: Option<PathBuf>`. Defaults are `127.0.0.1:8000`, 4 workers, queue size 64, and no TLS paths. Future clap code can populate it directly.
- `Config::from_env(ServeOptions) -> Result<Config, ConfigError>` uses `std::env::var`.
- `Config::from_lookup(ServeOptions, impl FnMut(&str) -> Result<String, std::env::VarError>) -> Result<Config, ConfigError>` permits deterministic tests without process environment mutation. It requests only `MESHDB_S3_BUCKET`, `MESHDB_TOKEN`, and `MESHDB_S3_PREFIX`.
- Config fields are private. `options() -> &ServeOptions`, `bucket() -> &str`, `namespace() -> &Namespace`, `token() -> &str`, and `admission_limit() -> usize` expose validated inputs. Clone the namespace when passing ownership to storage. Token access is intentional for HTTP authentication; Config's custom Debug redacts it.
- `ConfigError` implements Debug, Display, and Error. Diagnostics contain static descriptions and setting names, never supplied values, paths, OS diagnostics, or VarError payloads. Internal helpers `required` and `readable_file` have no external contract.

## Validation boundaries

Workers must be at least 1. Queue size is unsigned and may be zero. Checked addition produces the admission limit, which must be at most `tokio::sync::Semaphore::MAX_PERMITS`, inclusive. The constant comes from the installed pinned Tokio source, without duplicating its implementation.

Bucket and token must exist, be Unicode, and contain non-whitespace characters. Their accepted values remain unchanged. A missing prefix defaults to `meshdb-v0/`; an explicit empty or non-Unicode prefix fails. Storage's `Namespace::new` owns all prefix rules and trailing-slash normalization. No AWS credentials, region, dotenv, or credential files are read here. Storage retains its profile and role resolution chain.

TLS paths must both be absent or both present. Each supplied path must resolve to a regular file and successfully open for reading. Metadata from the opened handle confirms the file type, and the handle closes before construction returns. An initial metadata check avoids opening known special files. Readable symlink targets are accepted. R10 must reopen and validate PEM/key compatibility and initialize native Rustls before binding; files can change after this synchronous check.

## Checks

Four grouped integration tests include the actual config source with `#[path]` and alias `meshdb_server::storage`, so R04 need not export config yet. They cover defaults and overrides, prefix normalization, required settings and sanitized errors, redacted Debug, worker/queue bounds, and temporary TLS files. Unix unreadability checks run when mode-000 files cannot be opened by the test user. No network or S3 calls occur.

The test was written first; an initial direct rustc invocation failed because `src/config.rs` did not exist. Cargo initially waited on a peer's shared build lock.

Passing commands from the repository root. The direct target build uses existing compiled dependencies, includes the actual config source, and links the real storage implementation:
