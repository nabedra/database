## Public contract

```python
from meshdb import serve, Cluster, DB
from my_infrastructure import start_node, stop_node, list_nodes

serve(
    name="production",
    nodes=(2, 20),
    start_node=start_node,
    stop_node=stop_node,
    list_nodes=list_nodes,
)

# Separate administration/application processes:
cluster = Cluster("https://db.example.com", admin_token)
cluster.scale(8)
cluster.scale(8, wait=True, timeout=300)
cluster.autoscale(min_nodes=2, max_nodes=20)
state = cluster.status()
db = DB("https://db.example.com", app_token)
```

`serve` is the long-running API entry point. Deployment configuration supplies bind/advertise addresses, authentication, storage/metadata access and worker bootstrap settings. It does not deploy its own API hosts. No EC2/AWS-specific option is required by the cluster API. Infrastructure callbacks run in the server runtime, not the ORM caller. Worker nodes have a generic `meshdb worker` entry point. Optional infrastructure adapters may use any machine/container service; manual externally started nodes are supported explicitly.

An integer node setting maintains that many healthy nodes; a `(minimum, maximum)` pair enables autoscaling. `scale` replaces autoscaling with a fixed persisted target and returns after acceptance unless waiting was requested. Repeated requests for the same target do not create duplicate machines. `autoscale` replaces a persisted policy. A wait timeout stops waiting, not the underlying operation. Restarting an API replica attaches to persisted configuration rather than resetting an existing policy.

`start_node(request)` receives a stable provisioning request identity and worker bootstrap configuration and returns a resource identity. `stop_node(resource_id)` is idempotent and runs after safe drainage. `list_nodes()` reports resources belonging to this cluster so interrupted or ambiguous provisioning can be reconciled. The exact validated callback record and wire schemas are locked by A03 before implementation.

## Required behavior

- [ ] F01. One stable ORM endpoint fronts a separate, replaceable API tier. Any healthy API replica can accept requests.
- [ ] F02. Real network nodes execute the existing partition reads, query evaluation and mutation preparation. Cluster mode has no silent fallback to local execution on the API host.
- [ ] F03. Identical workers can accept operations and distribute partition work to peers. No specially configured permanent query-coordinator node is required.
- [ ] F04. A node supports multiple simultaneous queries/jobs up to configured capacity. Operation, partition execution and queued-work budgets cannot deadlock each other or grow without bounds.
- [ ] F05. Shared durable storage retains immutable partitions; node-local data is disposable. Scaling the compute fleet does not relocate authoritative table data.
- [ ] F06. Reads use one captured committed snapshot; global ordering, key tie-breaking, limit, projection, count, exact types, row limits and stale table identity remain correct.
- [ ] F07. Concurrent writes from different entry nodes preserve atomic batches and publication. Failures never publish partial replacements or lose acknowledged writes.
- [ ] F08. Durable operation identities/outcomes make supported retries safe across lost responses and replica replacement. Reusing an identity with a different payload fails; retention and uncertain outcomes are explicit.
- [ ] F09. Membership includes registration, readiness, heartbeat expiry, capacity and drainage. Requests only use ready nodes and unavailable capacity produces bounded overload/unavailability responses.
- [ ] F10. Persist desired capacity, lifecycle intents, resource identities and progress. Pending launches count toward provisioning decisions, but not serving capacity.
- [ ] F11. Safe scale-down stops new work, drains accepted work, and only then calls infrastructure termination. Failed drainage never authorizes unsafe removal.
- [ ] F12. Startup deadlines, failed/ambiguous callback reconciliation, bounded retries and failure replacement work across controller/API restarts.
- [ ] F13. One effective scaling controller owns changes at a time, with safe takeover and rejection of stale controllers. External provisioning calls use stable identities across takeover.
- [ ] F14. Autoscaling uses observed queued/running work and capacity, bounded minimum/maximum, startup awareness and conservative scale-down stabilization. Missing/stale observations cannot cause unsafe scale-down.
- [ ] F15. The public `serve`, `Cluster.scale`, `Cluster.autoscale`, `Cluster.status` and `meshdb worker` interfaces work end to end. Ordinary ORM callers need no infrastructure credentials.
- [ ] F16. Infrastructure callbacks are optional for externally managed workers, with explicit capability errors for unsupported provisioning requests.
- [ ] F17. Internal/admin authentication, verified transport configuration, bounded inputs/results, sanitized errors, shutdown and readiness are enforced at actual network entry points.
- [ ] F18. Storage/control interfaces are cloud neutral and exercised without an AWS account; existing S3 use remains compatible. Unsupported backend consistency capabilities fail explicitly.

## Agreed local conditional-object service contract

The development/acceptance backend is one Python standard-library process with SQLite on its own local disk, accessed over real HTTP by separate API/worker processes. Its availability is one service host; it is not represented as a production HA storage system. Cloud adapters must provide equivalent object semantics independently.

`GET /v1/objects/<safe-namespace-qualified-relative-key>` returns raw bytes and a quoted opaque ETag or 404. `PUT` at that path requires exactly one of `If-None-Match: *` or `If-Match: <etag>` and returns a new ETag after durable commit; a failed condition is 412. Both require bearer authentication from deployment configuration. `/health/live` and `/health/ready` disclose no data or credentials. Request bodies require a bounded Content-Length; reject chunked/ambiguous framing, invalid relative keys, invalid conditions and over-limit bodies. The local service caps each object at 80 MiB for legacy compatibility and bounds concurrent handlers. It has no delete/list routes.

Use SQLite transactions for atomic Create/Match across clients, a durable monotonically increasing version with no ABA, `synchronous=FULL`, and acknowledged-write recovery after restart. A response lost after commit remains an uncertain write to clients; never respond with a definite-not-applied classification after a possibly successful commit. Initialization and all SQL are parameterized and scoped to an explicitly supplied local database path. Tests use only fresh temporary state and owned processes. No cloud access, credentials from `.env`, or container downloads are required.
