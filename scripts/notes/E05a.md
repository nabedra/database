## Deferred live command and interfaces

After binary bootstrap, from the repository root:

```sh
PYTHONDONTWRITEBYTECODE=1 orm/.venv/bin/python scripts/acceptance_latency.py
```

This command has NOT been run. Only optional `--binary PATH` and `--report PATH`
arguments are accepted, plus `--help`. Default binary comes from ServerProcess,
`server/target/debug/meshdb-server`. Default report is
`artifacts/acceptance-latency-<uuid>.json`. Exclusive report creation precedes
configuration loading. Existing paths are refused. Setup failures save a
sanitized partial report when a fresh report can be reserved. Cancellation
during report setup makes a best-effort exclusive reservation, following the
corrected acceptance_lifecycle setup pattern.

Public CLI entry `main(argv=None)` returns 0 for success, 1 for failure and 130
for cancellation. Internal `run_dataset(number, name, initial, config,
binary=None)` returns a sanitized dataset record and requires the main thread.
`DATASETS` fixes its inputs; it is not a configurable benchmark interface.
Existing `Checks`, `require`, `safe_failure`, `load_config`, `ServerProcess`
and public ORM interfaces are reused unchanged. Live dependencies are imported
only after CLI parsing. Import and help do not load configuration.

## Fixture and measurement contract

Only `meshdb-testing` in `us-east-1` is accepted. The fixed allocations are:

- `config.allocate_prefix(7, 'latency-1')`: `test-7-latency-1-<run-id>/`.
- `config.allocate_prefix(8, 'latency-100')`: `test-8-latency-100-<run-id>/`.
- `config.allocate_prefix(9, 'latency-1000')`: `test-9-latency-1000-<run-id>/`.

Each dataset uses one ServerProcess with its config-guarded environment and one
table named `latency_rows`. Its schema is `id: int`, `text: str`, `number: int`,
`value: float`, `flag: bool`, keyed by `id`. Deterministic `row(index)` produces
bounded exact scalar values. IDs start at zero. One untimed insert_many seeds
1, 100 or 1000 rows. The measured single insert adds ID `initial`; the measured
10-row insert_many adds IDs `initial + 1` through `initial + 10`. Final counts
are 12, 111 and 1011. Each report retains the actual table ID, schema, key,
expected ID range, row recipe and latest verified count for later inspection.

Each operation has one sample. `perf_counter_ns` surrounds only the actual
public `table.insert`, `table.insert_many`, or prepared ordered
`query.collect` call. Input generation, query construction, seeding, method
result checks and exact row/count verification occur outside timing. The
ordered scan reads the complete table after both writes. Insert must return
None, insert_many must return exactly integer 10, and collect must match every
final scalar value and type in ID order. Untimed counts establish the before
and after sizes. No mutation is retried, including uncertain outcomes.

## Report and cancellation contract

Root fields are `version`, `status`, `cancelled`, `sample_count: 1`, fixed
experimental `notes`, `datasets`, and optional safe setup `failure`.
Each dataset reports sanitized bucket/region/allocated_prefix, initial and
expected/verified final counts, fixture metadata, measurements, labeled checks,
startup/shutdown/total process durations and total dataset elapsed seconds.
Process total spans the launch attempt through shutdown, including readiness.
Unavailable values remain null on partial failure.

Each measurement contains `operation`, `sample_count: 1`, `status`,
`row_count_before`, `row_count_after`, `batch_size`, `returned_count`, and
`elapsed_ms`. Batch sizes are 1, 10 and null for collect. Returned count is
null for insert, 10 for insert_many, and the verified result length for collect.
After counts are populated only after successful checks; failures can retain
unknown counts or elapsed times. No payloads, raw exceptions, arbitrary exception
class names, logs, token, environment or credentials enter the report.

All fixtures remain in S3. There are no AWS CLI commands, inspections, fixture
deletions or TLS resources. Every path attempts graceful process stop and reap;
forced or nonzero shutdown fails acceptance. SIGINT stops further dataset work,
defers interruption during process shutdown/report finalization, saves partial
results and exits 130. Ordinary failure also stops further datasets.
Console output contains only safe prefix/status summaries and the report path.

The fixed notes describe one-sample limits and the non-isolated AWS/network
environment. These end-to-end acceptance measurements do not support
percentiles, throughput, statistical estimates or performance comparisons.
