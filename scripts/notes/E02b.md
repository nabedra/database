Live acceptance is pending E02 after bootstrap and the Rust binary exist.

Run later from the repository root, with the local ORM installed:

```sh
PYTHONDONTWRITEBYTECODE=1 orm/.venv/bin/python scripts/acceptance_http.py --scenario all
```

The CLI accepts `--scenario types|api|atomic|all`, `--binary PATH`, and
`--report PATH`. Without `--binary`, `ServerProcess` selects
`server/target/debug/meshdb-server`. The report defaults to a fresh
`artifacts/acceptance-http-<uuid>.json`, covered by the existing `/artifacts/`
ignore rule. An explicit report path must be unused; existing files are
preserved. The runner reserves it before loading config or starting a server.
Import and `--help` construct neither config nor process objects.

The runner uses `load_config()` and `config.allocate_prefix()` with no bucket,
region, environment, or namespace override. It additionally requires the
supplied `meshdb-testing` bucket and `us-east-1` region. It never calls preflight,
an AWS API, bucket management, object inspection, or object cleanup. All fixture
population goes through the actual Rust HTTP server's guarded environment.
Each scenario allocates a fresh namespace and launches and stops one process:

- `types`: `test-1-scalar-types-<run-id>/`, retaining `scalar_strings` and
  `scalar_integers`, four rows each. Both key types and all four scalar types
  include Unicode, escaped/empty text, int64 endpoints, finite floats, signed
  zero, and both boolean values. Reads and ordered collection compare exact
  Python types, values, and floating point zero signs.
- `api`: `test-2-orm-api-<run-id>/`, retaining three rows in `guide_users`.
  Exercises the guide, every DB/Table method and query terminal, generator
  insertion, query branching, projection/filter/order/limit, limit-aware count,
  textual explain, replacement/insertion upserts, missing-row results, and a
  separate populated `disposable` table's drop.
- `atomic`: `test-3-atomic-errors-<run-id>/`, retaining the original row in
  `atomic_rows`. Checks duplicate single keys, late existing and intra-batch
  duplicates, malformed raw row/batch values, unchanged original contents and
  absence of earlier new rows, missing tables, dropped IDs/queries, unsupported
  operation and wrong-token authentication. `stale_table` is populated before
  its catalog drop; its S3 snapshot remains.

Normal operations use public `meshdb` methods. Malformed row/batch requests use
`_Transport.request()`. Because that method rejects unknown operation names
locally, the unsupported probe alone uses `_Transport`'s existing private
opener, URL, token and timeout with a stdlib `Request`. It checks the 400 JSON
error envelope and raises the ORM's base `MeshDBError`, the client's documented
class for unsupported operations. No ORM changes are needed. Expected errors
require exact exception class, code, HTTP status, and `not_applied` outcome.
Unknown outcomes abort the scenario without retry. Other scenarios requested
by `all` still receive separate namespaces and processes. Ctrl-C stops the
entire run after cleanup: no remaining scenarios are launched. The partial
report includes `cancelled: true` and the process exits with status 130.

Every constructed process is stopped in `finally`, including failed checks or
startup. Forced-stop helper exceptions or a nonzero exit fail the scenario.
No raw subprocess logs are retained in reports. The helper uses its private
temporary log by default. Fixtures remain in S3 after process exit, including
snapshots of explicitly dropped disposable tables.

Reports contain only explicit safe fields, with this shape:

```json
{
  "version": 1,
  "status": "passed|failed",
  "scenarios": [{
    "scenario": "types|api|atomic",
    "bucket": "meshdb-testing",
    "region": "us-east-1",
    "allocated_prefix": "test-1-scalar-types-<run-id>/",
    "fixtures": [{"id": "<table-uuid>", "name": "scalar_strings",
                  "row_count": 4, "state": "retained"}],
    "elapsed_seconds": 0.0,
    "checks": [{"label": "<fixed-check-label>", "status": "passed|failed"}],
    "status": "passed|failed"
  }]
}
```

`allocated_prefix` is null before allocation. `row_count` is the last verified
count, or null if a failure prevented counting. Dropped fixture entries use
`state: dropped_snapshot_retained` and keep their last verified pre-drop count.
Failed checks add an allowlisted `failure_type`; arbitrary exception names map
to `UnexpectedFailure`. Config/setup failure adds a top-level `failure` with
`label` and `failure_type`. Reports are saved on failure and exit status is 1.
No exception messages, credentials, tokens, config/process objects, response
payloads, or raw subprocess output enter the report. Stdout prints only the
report path and safe scenario/prefix/status summaries, or a fixed report
creation failure status.

allowed `--scenario all` to start subsequent servers. The coordinator made the
small correction: scenario and cleanup interruptions set an explicit
cancellation flag, main stops scheduling, and the sanitized partial report is
saved before exit 130. Setup interruptions also exit 130.

reproduced extra launches before the correction and passes afterward. It covers
