## Live interface, prepared only

From the repository root after bootstrap and the native binary build, run:

```sh
PYTHONDONTWRITEBYTECODE=1 orm/.venv/bin/python scripts/acceptance_lifecycle.py --scenario all
```

This exact command has NOT been run. `--scenario restart` and `--scenario https`
select one scenario. The only other options are `--binary PATH` and
`--report PATH`, plus argparse's `--help`. The default binary comes from
`ServerProcess`, currently `server/target/debug/meshdb-server`. The default
report is `artifacts/acceptance-lifecycle-<uuid>.json`. An explicit report path
must be fresh. Exclusive creation refuses existing files before configuration
loads or a process starts.

`main(argv=None)` returns 0 on success, 1 on failure, and 130 on cancellation.
Internal `run_scenario(name, config, binary)` returns a sanitized scenario
record. It runs on the main thread because final cleanup temporarily defers
SIGINT. A cancelled record stops the `all` loop before another scenario starts.
Cleanup reaps processes before removing temporary TLS files and restores the
prior signal handler. Cancellation retains the partial report.

Namespaces are freshly allocated through `config.allocate_prefix`:

- `test-4-restart-<run-id>/`
- `test-5-https-<run-id>/`

Restart creates one table through the public ORM, performs single and batch
inserts, updates a row, and deletes another. It captures the table ID, schema,
name, key, format, and expected remaining rows in memory. After observing a
zero exit from the first process, it creates a second `ServerProcess` with the
same config and namespace and a new `DB`. No setup writes are replayed. Catalog
discovery, metadata, exact sorted rows, count, and the deleted key are checked.
A post-restart update and full read check usability. Three populated rows remain.

HTTPS creates a caller-owned temporary directory and passes its new child
directory to `create_test_tls`. Both server certificate/key paths and `test_ca`
are passed to the real process helper for verified readiness. The runner checks
the native `https://` URL and constructs public `DB(..., ca_file=str(ca_cert))`.
It creates and populates a two-row table and reads it with that client. A fresh
client with default trust and no CA must fail a table-discovery READ with exactly
`TransportError`. The trusted client then reads the same rows again. This
positive/negative pair verifies use of the explicit test CA through public
behavior. No deliberate failing mutation or private transport inspection occurs.

Every registered process is stopped on success, error, and cancellation. A
nonzero exit or forced shutdown fails the scenario. Temporary certificates stay
alive until process exit is confirmed. If exit remains unconfirmed after a stop
failure, their private temporary directory is retained and the report includes
the fixed `local_tls_cleanup_exit_unconfirmed` failure label. The directory uses
explicit cleanup with no garbage-collection finalizer. S3 fixtures remain populated. There are
no mutation retries, S3 cleanup/deletion operations, or other AWS service calls.
Readiness polling remains the existing process helper's responsibility.

## Report contract

The JSON contract follows `acceptance_http`, with an explicit safe boolean
`cancelled` on both the root and scenario records:

- Root: `version` is 1, `status` is `passed` or `failed`, `scenarios` is a list,
  and `cancelled` is a boolean. Setup failures add `failure` containing only
  `label` and allowlisted `failure_type`.
- Scenario: `scenario`, fixed `bucket` and `region`, `allocated_prefix` or null,
  `fixtures`, `elapsed_seconds`, `checks`, `status`, and `cancelled`.
- Fixture: `id`, `name`, `row_count` or null, and `state` equal to `retained`.
  Counts reflect the latest successful count check, including in partial reports.
- Check: fixed `label`, `status`, and, on failure, allowlisted `failure_type`.
  Unknown exception types, including TLS fixture errors, become
  `UnexpectedFailure` under the shared sanitizer.

No exception messages, raw logs, row payloads, configuration, tokens, URLs,
certificate paths, certificate contents, or private keys enter the JSON report.
Report creation/write failures print fixed diagnostics and return failure.

## Process-exit cleanup correction

Quality review found that a failed stop could leave a process alive while
unconditional cleanup removed TLS material. The coordinator replaced automatic
temporary-directory finalization with explicit cleanup and checks every
registered process for an observed exit (or no launched process) first. A reaped
forced exit still fails acceptance but permits local cleanup; an unconfirmed
exit retains the directory even after garbage collection.

One focused regression reproduced the premature removal before the fix and
passes after it for unconfirmed, forced/reaped, and clean exits. It uses fake
process metadata and temporary local paths, with no TLS generation or services:

```sh
PYTHONDONTWRITEBYTECODE=1 orm/.venv/bin/python -m unittest discover -s scripts -p test_lifecycle_cleanup.py -v
```
